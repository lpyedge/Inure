# Chromium 邊緣控制端優化方案

2026-11-21 · 審查基準 `d9f7361` · 待實作

先修正 AI 觀察的基準與截圖對齊，再讓人通道按實際需求啟停，最後以量測選擇採集優化。每批可獨立驗收。第一批處理已在本機真 Chromium 重現的空增量漏更新與跨文件差分。需求及既有量測見[交接文件](../docs/HANDOFF_2026-11-21.md)。

## 第一批｜修正 AI 觀察基準與拒絕回包

1. 在現有 `FrameState` 與歷史池記錄採集分頁、文件代次、已套用的座標空間及輸出投影。固定採集分頁，提交前確認分頁與文件仍有效。採集中途切換時，丟棄候選結果，依觀察請求的總期限決定是否重採。
2. `since_frame` 以客戶端最後收到並套用的觀察為基準。`Done.frame_id` 依現行契約仍表示校驗幀。基準找不到、跨文件、座標空間改變或輸出投影不相容時回整幀。輸出投影至少涵蓋 `include_offscreen`、子樹與裁剪條件。
3. 第一版以候選觀察的比較結果判斷空增量。即使 CDP 沒發事件，也採集候選觀察。只在投影之外發生變化時，可以用空增量推進幀號。靜態頁的採集延遲可能增加，記錄改動前後的成本。
4. `act_with_fresh` 共用基準選擇邏輯。校驗快照仍屬於當前頁面且有效時，可以重用。500 ms 只代表重用的時間上限。取得狀態失敗時，保留原拒絕原因並明示最新狀態未取得。

實作入口見 [AI 通道](../crates/rig-edge-browser/src/ai.rs#L160)及[增量契約](../crates/rig-proto/src/observation.rs#L405)。涉及公開契約或安全邊界的變更依[專案規則](../CLAUDE.md)先確認。

| 測試 | 通過條件 |
| --- | --- |
| 同一頁完全靜止 | 回空增量，套用後的樹與完整觀察一致，客戶端基準仍可用 |
| 頁面改焦點，或動畫將按鈕水平移動 150 CSS px | 增量反映新的 `focused` 或 `bbox`，套用後與完整觀察一致 |
| 同文件改文字、表單輸入或巢狀容器捲動 | 增量反映完整觀察可見的變化，小範圍變更只送受影響子樹 |
| 整頁導航、A→B→A 切分頁或視口縮放 | 不相容的基準收到整幀，快照、定位表與座標空間屬於同一頁面版本 |
| 跨行程 iframe 點擊成功，走全頁校驗 | `Done` 回成功。客戶端使用最後收到的觀察查增量，可以直接套用或取得整幀 |
| 觀察後移除目標或切分頁，再送出動作 | 測試頁的副作用計數為零。HTTP 與 MCP 都附具體拒絕原因及可用的新狀態 |
| 使用者接管後頁面變更，AI 帶舊基準觀察 | 取得與接管後頁面一致的狀態才解除接管閂鎖 |

## 第二批｜統一 AI 截圖入口

`tree_image` 與獨立 `screenshot` 共用一條內部路徑。固定採集分頁，從完整觀察取得敏感區域，再依回應投影繪製編號。交付前核對文件與視口。如果文件識別或遮罩幾何無法確認，該次圖像交付失敗。`tree_image` 可保留已確認有效的文字和樹，獨立截圖回診斷錯誤。同頁重排需單獨驗證遮罩。 [現有截圖入口](../crates/rig-edge-browser/src/ai.rs#L294)

| 測試 | 通過條件 |
| --- | --- |
| 子樹或 token 預算排除敏感欄位 | 用合成夾具逐像素確認，該敏感區域仍完整遮罩 |
| 假 CDP 在採集與截圖之間切文件、改視口或拒絕識別查詢 | 兩個入口都不回傳圖像 |
| 同一文件內移動敏感欄位 | 實際敏感區域完整遮罩，或該張圖像被拒絕交付 |
| 穩定頁面，分別走 HTTP 和 MCP | 相同輸出投影下，遮罩與編號一致 |

## 第三批｜按觀看需求啟停，獨立計算音訊需求

通道開啟代表允許接入，實際觀看需求才啟動採集。以現有 WS 連線管理 Viewer 生命週期，分開記錄整頁畫面、DOM 鏡像、區域畫面與音訊需求。RTC 連線可承載多種資料，整頁畫面需求由實際選用的呈現方式決定。直接 HLS 播放另以有效播放請求計入需求。 [人通道啟動](../crates/rig-edge-browser/src/main.rs#L437) · [RTC 軌道與資料通道](../crates/rig-edge-browser/src/rtc.rs#L712)

1. 先做整頁採集啟停。首個消費者接入時先訂閱 CDP 事件，再啟動當前分頁的 screencast。最後一個消費者離開時停止採集。快取首幀只在分頁、文件和視口仍相符時回放。靜態頁若沒有新幀，從當前分頁補首幀。
2. 再拆開自動模式判斷與完整 DOM 鏡像。自動判斷只取媒體、畫布及互動元素等摘要，實際顯示 DOM 才啟動快照、差分及區域畫面。Viewer 依邊緣回報的實際視口換算座標。 [現有背景訂閱](../crates/rig-edge-browser/src/viewer.js#L1508)
3. 用兩個分頁驗證 R2。A 播放本機合成的 440 Hz 音訊，切到 B 看畫面。在 `rigsink` 及觀看端驗證 A 的聲音仍持續，同時確認 A 的畫面已停止採集。若現有混音路徑滿足需求，即沿用它。 [音訊採集](../crates/rig-edge-browser/src/rtc.rs#L396)

| 測試 | 通過條件 |
| --- | --- |
| 動畫頁開著，零觀看者、零直接 HLS 播放 | 停止完成後，整頁產幀、RGB 解碼及編碼計數都不再增加 |
| 靜態頁首次接入，或斷線期間換分頁後重連 | 第一張可用畫面來自當前分頁，以畫面特徵或像素判斷來源 |
| RTC 斷線，背景 DOM 判斷仍開啟 | WS JPEG 恢復且畫面持續更新。使用者的音訊設定保持原值 |
| 兩條連線快速接入並交錯關閉，包含啟動中斷線 | 剩餘消費者持續收幀，最後離開後採集停止，任務可回收 |
| DOM 模式觀看 B，A 在背景播放 | A 的背景聲音仍可辨識，A 的畫面採集停止，B 的 DOM 正常更新 |
| 直接播放 HLS，期間沒有 Viewer WS | 可取得播放清單和分片，播放需求結束後可回收資源 |

## 第四批｜量測後再做局部採集

使用同一台機器、相同 Chromium 版本與相同本機夾具跑 release。建議每個場景暖機 5 次，量 50 次。AI 場景涵蓋靜態頁、單一文字變化、焦點或表單變化、重排、跨行程 iframe、整頁導航。人通道涵蓋無觀看者、首幀及 RTC 回退。記錄 p50／p95、CDP 呼叫數、回應位元組數、首幀時間、CPU 及編碼器重建次數。量到基線後先定門檻，再比較變更前後。 [既有量測欄位](../crates/rig-edge-browser/src/main.rs#L574)

先驗證兩個候選。第一，用同一次 `DOMSnapshot` 取得必要的 DOM 欄位及幾何，量測是否能省下獨立的整頁 DOM 遍歷。第二，讓已在視口內且通過即時命中確認的元素跳過滾動及固定 60 ms 等待。若局部變更的成本仍超出目標，再對可明確映射的子樹實作 `Nodes` 局部重算。以完整觀察當作對照，逐案核對名稱、狀態、位置、父子關係與脫敏結果。 [全頁採集](../crates/rig-edge-browser/src/snapshot.rs#L135) · [元素定位](../crates/rig-edge-browser/src/ai.rs#L744)

## 首批工作與提交驗收

先寫三個現版會失敗的案例。焦點或幾何改變卻回空增量、跨文件仍回 delta、跨行程 iframe 動作後無法沿用客戶端已知基準。第一批完成後執行以下門禁。AV 用例使用隔離的本機 PulseAudio 與 `ffmpeg`／`ffprobe`。方案中的驗收案例需隨實作落地。

```bash
source scripts/local-env.sh
cargo fmt --all --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --all --locked
RIG_EDGE_IT=1 cargo test --locked -p rig-edge-browser --test edge_it
```
