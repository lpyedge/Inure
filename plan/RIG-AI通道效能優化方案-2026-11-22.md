# RIG AI 通道效能優化方案

2026-11-22 UTC · 基準版本 `f805c08` · agent-browser 0.21.4 · Chrome 157.0.8103.38

先修長列表的命中座標和同源 iframe 的採集缺口，再壓縮送給模型的觀察。agent-browser 的主要優勢是把可操作元素、完整快照和指定區塊的文字讀取分開。RIG 已有元素引用、局部快照、預算裁剪和增量，可沿用這些能力縮小差距。

## 差距在哪裡

上一輪共 275 次本機瀏覽器試驗。以下 token 為 9 種共同成功操作、45 組配對的每任務平均，使用 `cl100k_base` 對工具文字實算。

| 配置 | 觀察回包 | 操作指令＋回包 | 全程合計 |
|---|---:|---:|---:|
| agent-browser 精簡輸出 | 932 | 64 | 1,008 |
| agent-browser 原始觀察 JSON | 2,120 | 64 | 2,196 |
| RIG `text` | 2,152 | 99 | 2,289 |
| RIG `tree`＋增量 | 5,145 | 99 | 5,294 |

1. **agent-browser 平時只給足夠操作的資訊。** `snapshot -i` 給角色、名稱、狀態和引用，常見操作用短命令提交引用。讀文章或表格時，可以用完整快照或指定區塊的文字讀取。這輪精簡快照沒帶出兩題指定的正文，所需的額外讀取已計入。把 `refs` 等原始 JSON 欄位一併送出後，RIG `text` 的總量只高 4.2%。不含高密度表格的 40 組操作裡，即使比較原始 JSON，RIG `text` 仍用了 1,168 對 597 token，表示一般表單和小頁也值得壓縮。 [agent-browser 0.21.4 的快照與讀取選項](https://github.com/vercel-labs/agent-browser/blob/v0.21.4/README.md#snapshot-options)
2. **RIG 每列的座標和版面文字節點占了大部分可省空間。** `render_node` 輸出元素、狀態和邊界框，表格常同時出現 `cell → text → inlinetextbox`。我對 45 組既有 RIG `text` 回包離線重算。只省略座標為 **1,624**，只省略 `inlinetextbox` 為 **1,186**，兩者都省略為 **658 token**，較原始 **2,152** 少約 69%。這是渲染成本的實算，省略後的語義覆蓋與操作成功率仍待端到端驗證。 [RIG 渲染器](../crates/rig-edge-browser/src/snapshot.rs#L835) · [離線重算紀錄](../.temp/eval/paired-2026-11-22/optimization-token-replay.txt)
3. **RIG 的失敗成本遠高於成功回包。** 長列表的拒絕回包為 9,993 token，包含 18 token 的拒絕理由、3,304 token 的新快照文字與 6,671 token 的結構化整樹。原因是 `act_with_fresh` 用預設 `tree` 取得新鮮狀態，而 `text` 觀察沒有結構化增量基幀。同題已建立基幀的增量回包為 61 token。正常完成的 RIG 操作回包平均比對照短，指令的主要開銷是 `frame_id` 和巢狀動作結構。 [回包實作](../crates/rig-edge-browser/src/ai.rs#L487) · [MCP 序列化](../crates/rig-edge-browser/src/main.rs#L1676)
4. **長任務真正吃成本的是多輪觀察與未完成操作。** agent-browser 本輪通過 55/60，RIG 通過 50/60。長列表固定捲動後 agent-browser 5/5、RIG 0/5。同源 iframe 是 agent-browser 5/5、RIG 0/5，跨來源 iframe 則反過來。兩邊直接點擊視口外目標都沒有完成任務，其中 agent-browser 仍回報成功。Canvas 和上傳兩邊都通過。 [完整評估](../.temp/eval/paired-2026-11-22/report.md)

## 優先實施順序

| 順序 | 改動 | 驗收 |
|---|---|---|
| **P0.1** | 修正捲動後的 DOM 命中測試座標 | 長列表 5/5。首屏、內層捲動容器、遮擋與 iframe 的正反例都通過，正例只觸發一次目標事件 |
| **P0.2** | 補採同一 CDP session 內的子 frame AX 樹 | 同源 iframe 表單 5/5，跨來源 5/5，巢狀 frame 操作正確，導航或移除後的舊引用失效 |
| **P1.1** | 精簡模型用快照，指定區塊時使用現有 `subtree` | 固定配對的觀察回包至少下降 50%，文章、表格列關係、控制項狀態和成功率維持 |
| **P1.2** | 讓拒絕後附帶的觀察沿用呼叫端所用視圖 | 固定長列表反例的拒絕回包至少下降 50%，原始原因、正確恢復步驟與拒絕語義維持 |
| **P2** | 讓宿主處理結構化增量，按實際回包選整幀或增量 | 靜態頁保留空增量，動態頁採用的增量比等價整幀小，重建結果一致 |

這些百分比是建議驗收門檻。P0 兩項若通過且其餘場景維持基準，核心操作才會達到 60/60。按表逐項驗收，可區分成功率改善、回包減量和步數變化。

### P0.1 修正命中測試的座標轉換

**已確認。** 在原長列表夾具上，Chrome 捲到 `scrollY=4500` 時，目標按鈕的視口範圍為 `[16,411,172,446]`，CDP 四邊形中心約為 `(94,428)`。頁面的 `elementFromPoint(94,428)` 找到第 104 項，但實測 `DOM.getNodeForLocation(94,428)` 回報找不到節點，改用文件座標 `(94,4928)` 即命中正確的 backend node。RIG 的 `hit_backend_node` 目前把視口點直接交給該 CDP 命令。 [命中檢查實作](../crates/rig-edge-browser/src/browser.rs#L1186) · [Chrome 探針](../.temp/eval/paired-2026-11-22/optimization-cdp-hit.json)

在 `browser.rs` 的命中測試邊界做座標轉換。優先用現有的 `ViewState` 與 CDP 頁面度量，先確定各 session 的視口原點，再將命中點轉成該文件的座標。輸入注入仍使用它所需的視口座標。補測主文檔捲動、內層容器、頁面縮放、帶捲動的 iframe 及遮擋。既有 backend node／後代檢查和外層 iframe 遮擋檢查一併執行，命中無法確認時仍拒絕。 [座標度量](../crates/rig-edge-browser/src/browser.rs#L1109) · [CDP 命中測試](https://chromedevtools.github.io/devtools-protocol/tot/DOM/#method-getNodeForLocation) · [CDP 滑鼠輸入](https://chromedevtools.github.io/devtools-protocol/tot/Input/#method-dispatchMouseEvent)

視口外直達是後續能力。既有 `include_offscreen` 可暴露目標，但元素互動性檢查可能在 `scroll_into_view` 前拒絕。若要減掉長列表的 9 次試驗捲動，先設計顯式「捲到已觀察的元素 → 重新觀察 → 點擊」路徑，再評估是否值得合併為一次動作。合併前要確認仍可分辨目標替換、節點離開文件及虛擬列表尚未渲染等情況。由於這涉及允許參與動作的目標範圍，需依專案規則評審。 [元素校驗](../crates/rig-proto/src/observation.rs#L822)

### P0.2 採集同一 session 的子 frame

**已確認。** RIG 以 CDP session 為單位採集 AX 樹，因此現有路徑能收獨立 session 的跨來源 iframe。相同 Chrome 下，同源夾具的 `Page.getFrameTree` 找到一個子 frame，未指定 `frameId` 時 AX 樹沒有表單欄位。傳入子 `frameId` 後取得 `Case reference`，`DOM.getFrameOwner` 也能解析宿主。 [AX 採集實作](../crates/rig-edge-browser/src/browser.rs#L800) · [RIG 快照組裝](../crates/rig-edge-browser/src/snapshot.rs#L217) · [CDP 探針](../.temp/eval/paired-2026-11-22/optimization-cdp-probe.json) · [CDP AX 樹](https://chromedevtools.github.io/devtools-protocol/tot/Accessibility/#method-getFullAXTree)

從已授權頁面的 frame tree 定位同一 session 的子 frame，逐 frame 採集並掛回宿主節點。沿用 OOPIF 的 session 路徑，同一 frame 只採集一次。補足子 frame 的 DOM 屬性、脫敏及操作定位，跨 frame 行為以實際輸入與提交驗收。子 frame 導航、移除和頁面切換要使舊引用失效。測試覆蓋子 frame 的敏感欄位與其他分頁的隔離，採集或脫敏無法確認時跳過該 frame 並保留診斷。

### P1.1 精簡模型用的快照

先以現有 `mode=text` 作模型宿主的預設。已知目標區塊時用 `subtree` 避免整頁重送。現有 `budget_tokens` 是保守的字元估算，可用於限制大型輸出，仍要測表頭、提示與錯誤訊息會否被刪掉。 [現有投影與預算](../crates/rig-edge-browser/src/ai.rs#L104) · [接入方案](../docs/07-智能体接入方案.md)

接著在模型文字渲染省略常規座標，去除已由父層文字表示的版面節點，同時保留可操作 ID、禁用／選中／展開等狀態、可見性、必填和當前錯誤。正文、提示、列標題及儲存格要能用局部觀察讀回，重名控制項保留分辨所需的列或表單上下文。採集到的幾何和完整樹仍供校驗及截圖打碼使用。第一個版本可在受信宿主對已脫敏的回包做投影，先跑配對測試。如果要變更公開的 `mode=text` 輸出，先確認現有宿主解析器並按 AI 通道契約評審。 [文字轉義與渲染](../crates/rig-edge-browser/src/snapshot.rs#L653) · [觀察與動作契約](../docs/PERCEPTION.md)

### P1.2 控制拒絕回包體積

模型宿主可先把已有的最新狀態解析為文字，將結構化區塊留在程式側。下一步評審是否讓邊緣端針對文字呼叫方回傳可用的精簡新狀態，結構化呼叫方在相容基幀存在時取增量。設計需明確指出哪個公開觀察幀是基準，基幀缺失時仍應提供可讀的恢復資訊。測同一拒絕原因、相同後續操作成功率、完整一輪恢復的 token，以及沒有被拒動作的頁面副作用。 [拒絕語義](../docs/06-接口与调用.md#22-act) · [實作入口](../crates/rig-edge-browser/src/ai.rs#L487)

### P2 讓結構化增量服務於宿主

靜態頁的空增量實測為 43 token，表格的首個完整樹則是 17,754 token。宿主應保有已套用的結構化狀態，再把當前任務需要的文字投影送入模型。驗證相同投影的增量可完整重建後，比較其序列化體積與整幀，選用較小的回包。先重跑捲動、表格列狀態變更和 SPA 遷移，確認有收益再考慮改動增量結構。 [增量產生與重建](../crates/rig-proto/src/observation.rs#L408) · [呈現邏輯](../crates/rig-edge-browser/src/ai.rs#L314)

## 回歸評估

- 每個改動先加一個能重現原故障的 Chromium 斷言，再跑原 14 個核心案例，各配置至少 5 次。快照同時驗證所需資料、目標引用和狀態。操作以頁面事件及實際結果驗收。
- 固定 AB 版本、Chrome、視口、頁面及同題目標。分別記錄首個快照、每次狀態變化、觀察請求、操作指令、失敗恢復和完整任務成本。並列同一成功配對和全部試驗結果，精簡與原始輸出各自保持同一口徑。
- 以整體成功率、逐類失敗和實際作用次數作為回歸門檻。遮擋、舊幀、接管、敏感值遮罩、iframe 隔離與上傳目錄使用現有檢查及對應反例。 [安全模型](../docs/08-安全模型.md) · [評估方法](../docs/EVAL.md)

方案依據為上一輪原始回包、離線 token 重算及兩組 Chrome CDP 診斷。涉及 AI 通道契約、安全邊界、模型或憑證的變更依專案規則另行批准。 [原始紀錄](../.temp/eval/paired-2026-11-22/trials.jsonl) · [彙總](../.temp/eval/paired-2026-11-22/summary.json) · [專案約束](../CLAUDE.md)

## 實作後驗收

沿用同一 Chrome、1280×633 CSS 視口及本機夾具，對優化版 RIG 重跑 175 次。兩個純觀察案例在 `text` 和 `tree`＋增量各 10/10。核心操作在兩種配置各從 50/60 提升為 60/60，固定九次捲動的長列表與同源 iframe 都從 0/5 提升為 5/5，跨來源 iframe、Canvas、上傳各維持 5/5。視口外直接點擊 5 次皆安全拒絕，該反例的回包從 9,783 降到 419 token。

固定前後及 agent-browser 均成功的原 45 組操作配對，每任務平均如下。

| 配置 | 觀察回包 token | 操作與觀察總 token |
|---|---:|---:|
| RIG `text` 原版 | 2,152 | 2,289 |
| RIG `text` 優化後 | 560 | 698 |
| RIG `tree`＋增量原版 | 5,145 | 5,294 |
| RIG `tree`＋增量優化後 | 3,178 | 3,327 |
| agent-browser 精簡輸出基準 | 932 | 1,008 |

RIG `text` 的觀察回包少了 74.0%，全程少了 69.5%。已有幾何的主要可操作控件、Canvas 和 iframe 在文本保有座標，其他元素依靠語義、ID 及狀態。另以 Chromium 回歸測試覆蓋遮擋、捲動後命中、巢狀同源 iframe 填寫與提交、密碼截圖遮罩、移除後的舊引用拒絕、純文本拒絕回包及增量重建。工具文字以 `cl100k_base` 計數。模型服務訊息帳單、圖片 token 及公開網站 **未驗證（NOT VERIFIED）**。 [優化後逐次記錄](../.temp/eval/paired-2026-11-22/optimized-final.jsonl) · [前後彙總](../.temp/eval/paired-2026-11-22/optimization-summary.json)

`bash scripts/local-gate.sh` 退出碼 0。Rustfmt、Clippy、29 項真 Chromium 整合測試和 6 項 Python 自測全部通過。其餘 Rust 測試為 123 項通過、2 項標記忽略。 [門禁紀錄](../.temp/eval/paired-2026-11-22/optimized-final-gate.log)
