# 02 架构与技术方案

## 1. 设计原则（`CLAUDE.md` 硬约束的技术表述）

1. **Chromium 是唯一真相源**。边缘不缓存页面，只缓存「最近一帧快照 + 定位表」（AI）和「最近一帧 JPEG」（人）。
2. **语义优先，像素兜底**。能从无障碍树/DOM 拿到的结构，不去看像素。
3. **坐标统一为逻辑像素**，由边缘转换；AI 与观看端不接触物理像素。
4. **动作引用「元素 + 帧」，执行前必须校验**；被拒绝的动作不执行、不静默重试。
5. **被控端任何文本都是不可信数据**，不能触发高权限动作；面向模型的渲染做不可信分隔与声明。
6. **密码与敏感值永不出现**：输出前脱敏，不保留掩码长度，图像打码，审计不记输入内容。
7. **凭证只放内存/请求头，永不放 URL**（唯一例外：只读的媒体路径钥匙，见 [08](08-安全模型.md)）。
8. **一切有界**：缓冲、连接数、超时都有上限；数据路径禁止 `unbounded_channel` 与 `unwrap()`。

## 2. 总体架构

```
 AI 智能体 ──► HTTP /observe /act /screenshot.png ─┐
              MCP stdio (JSON-RPC)                 ├─► ai.rs AiChannel ───────┐
                                                   │     ├─ snapshot.rs（AX 快照引擎）
 人（观看页）─► GET / + /auth.js + /viewer.js       │     └─ changes.rs（页面变化日志）
              POST /session（换票）                 │                           │
              WS /ws（输入、chrome 命令、信令）      ├─► human.rs HumanChannel ──┼─► browser.rs ─► cdp.rs ─► Chromium
              GET /stream/{key}/…（HLS）            │     ├─ dom.rs（DOM 镜像）  │   （托管/挂靠）  （手写 CDP）
                                                   │     └─ rtc.rs（WebRTC）     │
                                                   └─► media.rs（音视频合流）────┘
        exec.rs（待命/执行/接管状态机，两通道共享）   chrome.rs（标签/导航状态）   encode.rs（libav 编码）
        auth.rs（令牌换票与票据）
```

同一进程内两个通道共享同一个 `Browser`（Chromium 连接）与同一个 `ExecControl`（执行状态机）。

## 3. 技术选型

| 点 | 选择 | 理由 |
|---|---|---|
| 浏览器控制 | **手写 CDP 客户端**（tokio-tungstenite） | 只需要子集；自管事件多路复用；`tap` 钩子保证变化记账的先后顺序 |
| 语义来源 | AX 树（`Accessibility.getFullAXTree`）+ DOM（`DOM.getDocument pierce`）+ `DOMSnapshot` 批量几何 | 语义优先。批量几何把中文维基一次观察的 CDP 调用从 1100 次降到 15 次（`EDGE_BROWSER.md §10`） |
| 元素 id | `IdMap`：(会话, backendNodeId) → `e<N>`，边缘生命周期内稳定、永不复用 | 跨帧同一元素 id 不变；`LocateMap` 记 id → (会话, backendNodeId) 供动作定位 |
| HTTP 服务 | axum；rustls TLS（非回环强制，缺证书自签） | 见 [08](08-安全模型.md) |
| 人通道视频（兜底） | CDP `Page.startScreencast`（JPEG）→ 原样透传 WS 二进制帧 → 观看端 canvas | 零重编码、无代际损耗；解码出的 RGB 只给 RTC/HLS 编码层，且**按需解码** |
| 人通道视频（主路） | **WebRTC**：str0m（Sans-IO）+ H.264；编码全局一份多会话扇出 | 比 JPEG 流省带宽；PLI→关键帧、BWE→码率 |
| 音频 | HTTP 服务且自拉 Chromium 时，程序启动私有 PulseAudio daemon 与 `rigsink`（null sink）；monitor 采集后 RTC 走 Opus、HLS 走 AAC | 仅自拉 Chromium 会接入私有 socket；挂靠和纯 stdio 不启动。音频启动失败只禁用音频，视频不受影响 |
| 兜底合流 | 进程内 libav → HLS，HEVC 主 + H.264 兜底，观看页按能力探测 | 弃 stdio ffmpeg 子进程（有代际损耗、无编码器反馈）。**运行时不需要 ffmpeg 命令行** |
| 编码 | libavcodec，运行时协商硬编（NVENC→QSV→VAAPI→Vulkan），全失败回落 libx264/libx265 | 不以任何开发机有无 GPU 为基准 |
| JPEG 解码 | **必须走 ffmpeg mjpeg**，禁用 image crate / zune-jpeg | zune-jpeg 解 Chromium 帧系统性偏绿（[03 §2](03-关键技术难点与解决.md)） |
| DOM 镜像 | 页内序列化器（节点 id 注册表 + MutationObserver 差分）→ 沙箱 iframe 重放；开 RTC 后走 `rig-dom` 数据通道 | 「关键帧请求」= `dom-resync`；seq 单调、缺口重同步 |
| 令牌随机源 | `getrandom` | 系统随机源不可用则终止，不退化为弱令牌 |
| 错误处理 | 没有统一的错误库，各 crate 沿用现有写法：`rig-eval` 用 `anyhow`，`rig-edge-browser` 用字符串错误，`rig-launcher` 用 `Box<dyn Error>`；新增代码跟随所在 crate；数据路径禁止 `unwrap()`（2026-11-24 经项目负责人确认，原“库用 thiserror、入口用 anyhow”的约定改为现状） | `CLAUDE.md` |

## 4. AI 通道核心流程

### 4.1 observe

1. **固定采集范围**：记录当前标签页及切换代次、主文档 `loaderId`、变化日志序号 `mark` 和视口。
2. **构建快照**：对范围内每个页面会话（主会话及其 OOPIF 后代）取 AX 全树 + DOM 映射 + DOMSnapshot 几何；子帧原点 = 父帧中 iframe 元素包围盒左上角；逐节点经 `element_core` 构造 `Element`；剪枝无语义的 generic 壳；脱敏（密码/敏感框整棵子树清值、清掩码名）。
3. **校验并存帧**：采集结束后核对标签页、文档与视口，变化时在原截止时间内重采。完整快照与定位表一起写入校验状态；已输出的结构化视图单独保留最近八帧。
4. **响应副本按请求裁剪**（`subtree` / `budget_tokens` / 视口外过滤），**存储帧保持全量**，被裁掉的元素凭 id 仍可操作。
5. **带 `since_frame`**：`tree` 模式用调用方最后套用的观察作为基帧。标签页、文档、坐标空间和输出投影相容时比较视图，返回空增量或可正确套用的增量。其余情况回整帧。
6. **`tree_image`**：再取整页截图，敏感区域取自**完整**快照打黑块并叠加编号；采集期间换页则**不交付截图**。

### 4.2 act

校验链，任何一项失败都**不执行**：

1. 通道闸门；接管闩锁（接管后未重新 observe，直接 `Aborted`）。
2. `navigate`：origin 白名单（`--url` 的 origin + `--allow-origin`）。
3. 陈旧校验：
   - **元素目标**：请求帧等于最新存储帧时，先做**单元素快速复核**（只取该元素的 AX 节点 + DOM 属性 + 位置，约 4 次 CDP，与存储帧比 role/name/states/bbox，容差 2px）。它**只确认、不裁决**：任何不一致、出错、不适用一律退回整页快照由 `check_element_target` 裁决。
   - **坐标目标**：帧号必须严格等于存储帧且落在视口内；点击/输入/按键再做**实时复核**。
4. 执行前后各一个中断检查点；多步动作在每个副作用前再查（`Select`、`Upload` 写入前同样检查）。
5. **执行后按需观察**：`Done.frame_id` 是动作所基于的校验帧。下一次 `observe` 仍以调用方最后套用的观察作为增量基帧。
6. **页面状态类拒绝**附最新状态，增量基帧须满足观察的相容条件。本次动作采集的校验帧在 500 ms 内且标签页、文档、视口和结构均有效时可复用。
7. **幂等**：`request_id` + 请求指纹缓存终局结果，TTL 10 分钟、上限 256；`act` 串行。
8. `type` 点击目标后**复核实时焦点**确属目标，才向目标自己的会话插入文字；否则拒绝。

### 4.3 变化日志（`changes.rs`）

- CDP 读泵同步把事件归类写入 512 条的有界环形日志：`Document`（文档更新、跨文档导航、同文档导航）或 `Nodes`（属性/文本/子节点增删/内联样式失效）。
- `since(mark)` → `None | Nodes(≤64) | Document`；基线被淘汰或节点过多 → `Document`（保守：宁多采，不漏变）。
- 实测结论（Chromium 156）：文字变化 = 删旧文本节点 + 插新文本节点；`class` 改动只报属性变化；**滚动零通知**；`Accessibility.nodesUpdated` 从不触发，**不可用**。

## 5. 人通道核心流程

### 5.1 画面怎么来

**帧泵**对「观看标签」开 screencast，每帧：读 JPEG 真实尺寸（不信 screencast 元数据）→ 归类为整页帧 / 内容帧（视频等子区域，按矩形贴回干净底图）→ 整页帧记入 `last_frame`（新连接回放）并广播。RGB 是**惰性**的：存原始 JPEG，RTC/HLS 取用时才解码，每帧只解一次。

### 5.2 四种呈现

| 呈现 | 数据 | 何时用 |
|---|---|---|
| canvas（WS JPEG） | WS 二进制：8 字节头（宽/高 u32 小端）+ JPEG | 默认视频模式；RTC 未连通/回退 |
| RTC 视频 | str0m H.264（+ Opus 音频） | 视频模式主路；连通后该连接**停发 WS 帧** |
| HLS | HEVC/H.264 + AAC | RTC 连不通的兜底；`--av` |
| DOM 镜像 | 快照 + 差分（WS 或 `rig-dom` 数据通道） | 页面以表单/文章/后台为主 |

**连接级需求记账**（避免白送带宽）：WS JPEG 帧是否发给某连接只看它自己上报的 `jpeg-demand`；DOM 订阅同连接幂等、断开统一释放；RTC 编码器按「有无会话」启停。

**模式自适应**（`viewer.js`）：每张 DOM 快照裁决——视频面积 >10% 且可交互元素 <3、或大区域 >30%、或 canvas >20% → 视频，其余 → DOM。带迟滞：新裁决持续 3 秒且距上次自动切换 ≥3 秒；每次导航最多自动切 2 次；手动切换锁定到下次导航。

### 5.3 输入与标签

- 视频模式发屏幕坐标（观看端按帧尺寸换算）；DOM 模式发页面坐标；文本、组合键、输入法、剪贴板见 [EDGE_BROWSER.md §9](EDGE_BROWSER.md)。
- 自拉起模式下每个标签一个页面会话（含 OOPIF）；**AI 的「主页面」始终跟随人当前看的标签**。挂靠模式快照只收当前授权标签。
- `chrome://` 等内部页：只有外壳状态、无快照（WebUI 全在 shadow DOM 里，镜像出来是空壳），观看端回落视频模式。

## 6. 执行状态机（`exec.rs`）

```
        begin_observe / begin_act
 Idle ───────────────────────────► Executing（在途计数 +1，人侧遮蔽输入）
   ▲                                   │ 每个 call 结束 end()（计数 -1）
   │   最后一个结束后 2 秒保持窗         │
   └───────────────────────────────────┘
 request_abort（强制接管 / 关闭 AI 通道）：立即 Idle、取消代次 +1、置接管闩锁
```

- **取消代次（`cancel_epoch`）**：每个 call 开始时领取当时的代次，`request_abort` 使之递增，旧代次的 call 在下一个检查点中止；新 call 领取新代次，旧 call 的取消**永不复活**。
- **接管闩锁**：置位后 `act` 一律拒绝；只有**接管之后新开始**的 `observe` 成功才能解闩，接管前在途的旧 `observe` 成功返回也不得解闩。
- **保持窗**由「在途数归零」那一刻领取的序号标识：后归零的保持窗使先前的作废，与 call 的开始先后无关。
- 在途计数放原子里，`ExecHandle` 的 `Drop` 兜底归还，任务被取消也不泄漏。

## 7. 鉴权与路由（概要，详见 [08](08-安全模型.md)）

- **路由拆分**：Viewer 路由（`/`、`/auth.js`、`/viewer.js`、`/health`、`/ready`、`/session`、`/session/refresh`、`/channels`、`/print.pdf`、`/stream/*`、`/ws`）与 AI 路由（`/observe`、`/act`、`/screenshot.png`）；另有 `/health`、`/ready` 挂在 Viewer 路由上。`--stdio` 模式只挂 Viewer 路由。
- **启动令牌**由启动程序随机生成并传入，只用于换票，或由非浏览器客户端直接作 Bearer 调用 AI 路由。
- 换得 `access`（短效）+ `refresh`（无时限、使用即轮换）；票据只存内存，重启即失效。
- WebSocket 无法设请求头：连上后 3 秒内首帧认证。HLS 用原生 `<video src>` 无法带头：用只读路径钥匙。
- 观看页内嵌：`--embed-origin` 白名单同时驱动 `frame-ancestors` 与 `postMessage` 授权。

## 8. 临时资源与退出

| 资源 | 位置 | 退出时 |
|---|---|---|
| 一次性 profile | `<tmp>/rig-edge-<pid>`（未给 `--profile-dir`） | Chromium 关闭后删除 |
| PulseAudio 私有运行目录 | `<tmp>/rig-edge-<pid>-pulse`（仅 HTTP + 自拉 Chromium 且有 PulseAudio 时） | 删除 |
| 临时上传目录 | `<tmp>/rig-edge-<pid>-uploads`（未给 `--cache-dir`） | 删除 |
| HLS 分片（屏幕画面） | `<tmp>/rig-edge-hls-<pid>/`（其下每次管线一个 `g<N>/` 代次目录） | 删除 |
| 你指定的目录 | `--profile-dir` / `--cache-dir` | **不动** |

SIGINT/SIGTERM/stdin 关闭走优雅退出：先发 CDP `Browser.close` 让 Chromium 落盘，超时才硬杀。SIGKILL 与崩潰无法兜底，会留下残余目录。

## 9. 编码与资源上限

- 编码：HEVC = libx265（veryfast、1.5Mbps）；H.264 = libx264（veryfast、2.5Mbps）；关键帧间隔 20 帧；AAC 48kHz 128k。HLS fMP4，`hls_time 1`，列表 6 段，自动删旧段。
- RTC：帧率上限 30fps，码率上限 8Mbps（`rtc.rs` 常量）。
- 变化日志 512 条；帧历史池 8 帧；幂等缓存 256 条 / 10 分钟；Upload ≤20 个文件、单文件 ≤200MiB；WS 首帧认证 3 秒；access 15 分钟。
- 所有缓冲与连接数都有界；`/health` 暴露在途数、帧计数、各阶段延迟分位。
