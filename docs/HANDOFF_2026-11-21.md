## 1. 项目定位与硬约束

**一句话**：一个 Rust 二进制 `rig-edge-browser`，直连 Chromium（CDP），把同一个真实浏览器同时开放给两类消费者：

- **AI 通道**：把页面压成紧凑的无障碍（AX）语义快照；动作以“帧号 + 元素 id”执行，执行前校验。
- **人通道**：把画面（和声音）流给人看，并把人的鼠标/键盘/剪贴板送回页面。

本机（stdio / 回环 HTTP）或局域网（HTTP + 令牌）直连即完整形态；中转/网关已整仓移除，不在本仓库。

**`CLAUDE.md` 的硬约束（改动前必读）**

- 只支持 Chromium；不做 iOS、桌面 RDP/VNC。
- 语义来源优先：能从 AX 树/DOM 拿到的结构，不去看像素；像素只是兜底。
- 坐标统一为**逻辑像素**，边缘转换；AI 与观看端不接触物理像素。
- 动作引用**元素 + 帧**，执行前必须校验；被拒绝的动作**不执行、不静默重试**。
- 被控端任何文本都是**不可信数据**；密码/敏感值永不出现（输出前脱敏、不保留掩码长度、图像打码、审计不记内容）。
- 凭证只放内存/请求头，**永不放 URL**（唯一例外：HLS 播放器的 `?token=`，见 SECURITY_DESIGN）。
- 挂靠模式下快照只收录当前授权的标签页会话（B1），不把其他标签页送进 AI 观察范围。
- 所有缓冲、连接数、超时都有上限；数据路径禁止 `unbounded_channel`、禁止 `unwrap()`。
- **必须停下来问的**：改 AI 通道契约（`rig-proto` 的 Observation/Action）、改安全边界、评估用的模型与凭证、超范围功能。
  （2026-11-21 起，用户已授权“可适当调整 AI 通道数据 schema”，见 §7。）
- 工作方式：一次一个改动；先写测试再写实现；`cargo fmt --all` + `cargo clippy --all-targets -- -D warnings` + `cargo test` 全绿；
  评估数字必须来自实际运行并注明环境。

## 2. 架构总览

```
 AI 智能体 ──► HTTP /observe /act /screenshot.png ─┐
              MCP stdio (JSON-RPC)                 ├─► ai.rs  AiChannel ──────┐
                                                   │      ├─ snapshot.rs（AX 快照引擎）
 人（观看页）─► WS /ws（输入、chrome 命令、信令）    │      ├─ changes.rs（页面变化日志）
              GET / (viewer.html + viewer.js)       ├─► human.rs HumanChannel ─┼─► browser.rs ─► cdp.rs ─► Chromium
              /stream/* (HLS)                       │      ├─ dom.rs（DOM 镜像）│  (托管/挂靠)   (手写CDP)
                                                    │      ├─ rtc.rs（WebRTC）   │
                                                    └─► media.rs（音视频合流）───┘
                  exec.rs（待命/执行/接管状态机，AI 与人通道共享）  chrome.rs（标签/导航状态）  encode.rs（libav 编码）
```

## 3. 技术选型与理由

| 点 | 选择 | 理由 / 备注 |
|---|---|---|
| 浏览器控制 | **手写 CDP 客户端**（tokio-tungstenite，flatten 会话） | 只需要子集；自管事件多路复用；`tap` 钩子保证变化记账顺序 |
| 语义来源 | AX 树（`Accessibility.getFullAXTree`）+ DOM（`DOM.getDocument pierce`）+ DOMSnapshot 批量几何 | 语义优先；批量几何把中文维基 CDP 调用 1100→15（`EDGE_BROWSER.md §10`）。`Accessibility.nodesUpdated` **不触发，不可用** |
| 元素 id | `IdMap`：(会话, backendNodeId)→`e<N>`，边缘生命周期内稳定、永不复用 | 跨帧同一元素 id 不变；`LocateMap` 记 id→(会话, backendNodeId) 供动作定位 |
| HTTP 服务 | axum；可选 TLS（rustls，非回环强制） | 令牌：`Authorization: Bearer` 或 `?token=`（仅给媒体元素） |
| 人通道视频（默认） | CDP `Page.startScreencast`（JPEG q60，最大 1920×1200）→ **原样 JPEG 透传**到 WS 二进制帧 → 观看端 canvas | 零重编码、无代际损耗；解码出的 RGB 只给 RTC/HLS 编码层，且**按需解码** |
| 人通道视频（主路） | **WebRTC**：str0m（Sans-IO）+ H.264 低延迟；编码全局一份多会话扇出 | 比 JPEG 流省带宽；PLI→关键帧、BWE→码率 |
| 音频 | PulseAudio **虚拟声卡 `rigsink`**（null sink）monitor 采集；RTC 走 Opus，HLS 走 AAC | 页面声音进虚拟声卡，不依赖物理声卡；PulseAudio 缺失时音轨静默缺席 |
| 兜底合流 | 进程内 libav → HLS，HEVC 主 + H.264 兜底，观看页 MediaSource 探测 | 弃 stdio ffmpeg 子进程（LIU 2026-11-19 定案）；**不需要 ffmpeg 命令行**，仅测试后半段用 `ffprobe` |
| 编码 | libavcodec，运行时协商硬编（hw_frames_ctx），全失败回落软编 | 不以任何开发机有无 GPU 为基准；unsafe 全收敛在 `encode.rs` |
| JPEG 解码 | **必须走 ffmpeg mjpeg**，禁用 image crate/zune-jpeg | zune-jpeg 解 Chromium 帧系统性偏绿（2026-11-19 实测） |
| DOM 镜像 | 页内序列化器（节点 id 注册表 + MutationObserver 差分）→ 沙箱 iframe 重放；传输 WS，开 RTC 后走 `rig-dom` 数据通道 | “关键帧请求”= `dom-resync`；seq 单调、缺口重同步 |
| 变化检测 | CDP 结构类通知 → `changes.rs` 日志 | 滚动/纯视觉变化无通知，需另读视口（见 §6） |
| 错误处理 | 库 `thiserror`，二进制 `anyhow` | `CLAUDE.md` |
| 测试 | 单元（含假 CDP）、真 Chromium 集成（`RIG_EDGE_IT=1`）、Playwright（仅探针/基准脚本） | 见 `EDGE_BROWSER.md §12` |

## 4. 两个通道的核心流程

### 4.1 AI 通道：observe（观察）

1. 采集前记：主文档 `loaderId`、变化日志序号 `mark`、视口状态 `view_state`。
2. `build_observation`：对范围内的每个页面会话（主会话及其 OOPIF 后代）取 AX 全树 + DOM 映射 + DOMSnapshot 几何；
   算 iframe 偏移（子帧原点 = 父帧中 iframe 元素包围盒左上角）；逐节点经 `element_core` 构造 `Element`；剪枝 generic 壳；
   `scrub` + `redact_sensitive` 脱敏（密码/敏感框整棵子树清值、清掩码名）。
3. 原子存入 `FrameState { obs, locate, loader, at, mark, view }`（B4 帧原子性）；同时入历史池（最近 8 帧）。
4. 响应副本按请求裁剪（`subtree` / `budget_tokens` / 视口外过滤），**存储帧保持全量**，被裁掉的元素凭 id 仍可操作。
5. **带 `since_frame`**：若是最新存储帧且 ①文档没换 ②无结构类通知 ③视口没动 → **空增量、不采集**；否则采集后回 `delta`（在历史池）或整帧。
6. `mode=tree_image`：再取整页截图，敏感区域取自**完整**快照打黑块，叠加编号；采集期间换页则**不交付截图**。

### 4.2 AI 通道：act（动作）

校验链，任何一项失败都**不执行**：

1. 通道闸门、接管闩锁（接管后未重新 observe，act 直接 `Aborted`）。
2. `Navigate`：origin 白名单（`--url` 的 origin + `--allow-origin`）。
3. 陈旧校验：
   - **元素目标**：请求帧 == 最新存储帧时先试**单元素快速复核**（`fast_confirm`：只取该元素的 AX 节点 + DOM 属性 + 位置，
     约 4 次 CDP，与存储帧比 role/name/states/bbox，容差 2px；要求同文档、目标在主会话）。**只确认、不裁决**：任何不一致/出错/不适用
     一律退回整页快照由 `check_element_target` 裁决。命中/退回计数见 `/health` 的 `act_precheck`。
   - **坐标目标**：帧号必须严格等于存储帧 + 落在视口内；点击/输入/按键再做**实时复核**（新采一帧比对命中元素/焦点元素）。
4. 执行前/后各一个中断检查点（强制接管 → `Aborted{UserTakeover}`）；多步动作每个副作用前再查。
5. **执行后不再刷新**（操作与呈现解耦）：`Done.frame_id` = 动作所基于的校验帧。要看新状态，调用方 `observe(since_frame=Done.frame_id)`。
6. **被拒**（`StaleFrame/UnknownElement/NotInteractable/OutOfBounds`）：边缘自己附带最新状态——请求帧在历史池 → `delta`，否则整帧；
   <500ms 的帧复用不重采。HTTP 在 `result` 旁加 `delta`/`observation` + `text`；MCP 多附文本块。
7. 幂等：`request_id + 请求指纹` 缓存终局结果（Done/Rejected），TTL 10 分钟、上限 256；act 串行（`act_lock`）。

### 4.3 变化日志（`changes.rs`，呈现一侧的地基）

- CDP 读泵同步把事件归类写入有界环形日志（512 条）：`Document`（`DOM.documentUpdated`、`Page.frameNavigated`、`navigatedWithinDocument`）
  或 `Nodes`（属性/文本/子节点增删/内联样式失效；子节点增删记**父节点**）。
- `since(mark)` → `None | Nodes(≤64) | Document`；基线被淘汰或节点过多 → `Document`（保守，宁多采不漏变）。
- 探针结论（真 Chromium 156）：文字变化 = 删旧文本节点 + 插新文本节点；`class` 改移位只报 attributeModified；**滚动零通知**；
  `nodesUpdated` 从不触发。

### 4.4 人通道：画面怎么来、怎么送

**帧泵**（`human.rs`）：对“观看标签”开 screencast，每帧：
- 读 JPEG 真实尺寸（`jpeg_dims`，不信 screencast 元数据）→ 归类：整页帧 / 内容帧（视频等子区域，按矩形贴回干净底图，V02）/ 无法归属。
- 整页帧：原样 JPEG 记 `last_frame`（新连接回放）+ 广播；**RGB 惰性**：存原始 JPEG，RTC/HLS/V02 取用时才解码+归一化，每帧只解一次。

**四种呈现**（观看页 `viewer.js` 决定显示哪种）：

| 呈现 | 数据 | 何时 |
|---|---|---|
| canvas（WS JPEG） | WS 二进制：8 字节头（宽/高 u32 小端）+ JPEG | 默认视频模式；RTC 未连通/回退 |
| RTC 视频 | str0m H.264（+Opus 音频） | 视频模式主路，连通后该连接**停发 WS 帧** |
| HLS | HEVC/H.264 + AAC | RTC 连不通的兜底；`--av` |
| DOM 镜像 | 快照 + 差分（WS 或 `rig-dom` 数据通道） | 内容以表单/文章/后台页为主 |

**连接级需求记账**（避免白送）：
- `jpeg-demand`（观看端上报“我是否在用 WS JPEG”）：**WS JPEG 帧是否发给某连接只看它**（本轮修复：此前后台 DOM 订阅会误停 JPEG）。
- DOM 订阅 `dom-start/stop` 同连接幂等（D01），连接断开统一释放（D02）。
- RTC feeder 用 `want` 计数：有 RTC 会话才编码。

**模式自适应**（`viewer.js` F-08/U03）：连接即起后台 DOM 感知会话，每张快照裁决——`视频面积>10% 且可交互元素<3`、或 `大区域>30%`、或 `canvas>20%` → 视频，
其余 → DOM。迟滞：新裁决持续 3s 且距上次自动切换 ≥3s；每次导航最多自动切 2 次；手动切换锁定到下次导航；右键菜单可关。

### 4.5 输入与交互模型

- **待命/执行/保持窗/强制接管**（`exec.rs`，`EDGE_BROWSER.md §7.1`）：AI 平时只连通不处理；任一 `tools/call` 到达进入执行（人侧遮蔽输入、显示 AI 幽灵指针）；
  在途 call 全返回后 2 秒保持窗回待命；人点击/按键即强制接管，在途 act → `Aborted`，须重新 observe 才解闩。
- **人的输入**：视频模式发屏幕坐标（观看端按帧尺寸换算）；DOM 模式发页面坐标（`dom:1`，直达分发）；文本/组合键/IME/剪贴板（文本+图片双向）见 `EDGE_BROWSER.md §9`。
- **幽灵指针**：边缘 150ms 轮询执行状态，经 WS `ghost` 消息推位置/轨迹/意图标签，观看页在当前显示面叠加绘制，不注入页面。

### 4.6 标签页与会话

- 自拉起：每标签一个页面会话（含 OOPIF）；**AI 的 `main()` 始终跟随人当前看的标签**（B4/§7）。挂靠模式快照只收当前授权标签（B1）。
- 标签栏顺序用 `stable_tab_order` 保持稳定；新标签自动放行 `runIfWaitingForDebugger`；多标签且帧停滞时把观看标签切回前台（仅自拉起）。
- `chrome://` 等内部页：只收内部页状态、无快照（内部页把关）。

### 4.7 安全

直连令牌（非回环必须设，且强制 TLS，缺证书自动生成自签）；origin 白名单；脱敏三层（AX 构造期、`scrub`、`redact_sensitive`）+ 图像打码；
日志/审计不含输入内容；DOM 通道承载字段值，安全性靠传输加密；快照会话隔离见 `SECURITY_DESIGN_2026-11-19.md`。

## 5. 各种操作情况的具体走向（速查）

| 情况 | 走向 |
|---|---|
| AI 点元素，页面没变 | 快速复核命中（~4 次 CDP）→ 执行 → `Done`（立即返回）；之后 `observe(since)` 空增量，不采集 |
| AI 点元素，页面自己变了/目标被移走 | 快速复核失败 → 整页快照 → `check_element_target` 拒绝 → `Rejected` + 最新状态（delta/整帧） |
| AI 点坐标/按键/输入 | 帧号严格相等 + 实时复核（新采一帧比对命中元素/焦点）→ 执行 |
| AI 导航 | origin 白名单 → 导航；之后换文档，旧 id/旧帧一律失效 |
| AI 上传文件 | 目标须 `<input type=file>`，路径须存在、≤20 个、≤200MiB；`DOM.setFileInputFiles` |
| AI 带 `since_frame` 观察 | 没变→空增量；局部变/大变→重新采集（目前局部变也整页采）；换页→整帧 |
| 人在视频模式点击 | 观看端换算坐标 → WS → 人通道注入；执行期被 AI 遮蔽则丢弃 |
| 人在 DOM 模式点击 | 页面坐标 `dom:1` → `handle_ws_dom` 直达；镜像内输入监听后转发 |
| 人切标签 | `set_main` 切换；screencast/DOM 观察者/AI 的 `main()` 跟随；旧标签数据按会话隔离 |
| 人强制接管 | 遮蔽期人点击/按键 → `ExecControl` 取消在途 act（`Aborted`）→ 接管闩锁，须重新 observe |
| 页面自己变（定时器/动画） | DOM 镜像：页内 MutationObserver 差分；AI：变化日志标记，下次 `observe(since)` 重采；画面：screencast 照推 |
| 整页换页 | `Page.frameNavigated` → 日志 `Document`；观看端模式裁决按新 URL 重置迟滞 |
| 视频/音频页 | 自动模式切视频；RTC 带 Opus；RTC 不通落 HLS；DOM 模式下 RTC 音频与画面解耦（只藏画面不掐声） |
| RTC 断线 | 该连接 WS 帧自动恢复（`jpeg-demand` 为真）；首张新画面靠 `last_frame` 回放 |
| 新观看者接入 | 先回放最近一帧；先发当前 chrome 状态 |
| 通道关闭 | AI 关：`/observe` `/act` `/screenshot.png` 回 409；人关：WS 被拒，screencast 停 |

## 6. 已知局限（现状如实）

- **纯视觉变化无通知**：滚动（已另读视口补上）、CSS 动画、`:hover` 显隐不产生 DOM 事件；“没通知”≠“页面没变”。
- **局部变化仍整页重采**：`observe` 只在“没变/换页”两端省采集；“变了一块”还没有按节点补算。
- **子帧（OOPIF）元素**不走快速复核（需帧偏移），仍整页快照裁决。
- **`observe` 的 `subtree/budget_tokens`** 仍是全量采集后裁剪（只省 token，不省采集）。
- **帧泵常驻**：人通道开启（`--human` 或闸门打开）即启动 screencast 与帧泵，**与是否有观看连接无关**（见 §7 差距 G1）。
- **`rig-eval` 评估运行器**对 `Done.frame_id` 新语义（校验帧，非动作后新帧）的使用**待核实**。
- 单测 `media::tests::single_rendition_builds_one_output` 偶发失败，疑似改进程级环境变量与并行单测互扰（**未验证**）。
- 实测数字均为 **debug 构建、本地回环、单次运行**，release/真实网络未测。

## 7. 需求页（用户在本轮明确提出的方向，后续优化的目标）

> 以下是用户（LIU）2026-11-21 的原话要点，按主题整理。它们是**后续优化的验收标准**。

**R1 不观察不传送，只传最小变化。**
没有连接人工通道或 AI 通道，就不做对应的数据采集；连接后以**当前 tab** 采集；尽量只传输**具体变化内容**。
**AI 通道和画面通道一样处理；DOM 模式和视频模式同样处理。**

**R2 声音是特例。**
有声音的 tab 允许继续以**非前台方式**发声音，但它的**画面可以被忽略**（不采集不传送）。

**R3 操作与呈现是两个逻辑，不要混在一起。**
操作可以造成呈现大变化，也可能仅仅是一个加载中的图标动画；人工与 AI 的所有操作交互都是同一个逻辑——
操作只回答“有没有执行”，呈现由变化检测驱动、按变化量送出（没变就不送，局部变就送局部，换页才送整页）。

**R4 程序负责保险，不要求使用者迁就。**
AI 通过命令要求操作某元素，若已不可交互/不在原位，**程序**返回失败 + 具体原因，同时送出**最新状态**让 AI 继续；
不是让 AI 自己想办法多要数据。“服务好 AI 通道与人工画面两类对象：尽量少带宽、合理处理对方操作、及时给出反馈；
**不是要求使用者必须如何如何才能用好**。”

**R5 允许调整 AI 通道数据 schema。**
目标：和实际页面对应、数据合理且不大、**保持局部刷新能力**。（审查结论：元素 id 已绑定真实节点且跨帧稳定，公开 schema 基本不用改；
本轮只改了 `Done.frame_id` 语义，其余在内部扩展。）

### 现状与需求的差距（下一步优化清单，按建议优先级）

| # | 差距 | 对应需求 | 建议 |
|---|---|---|---|
| G1 | 帧泵/screencast 在人通道开启后常驻，不看是否有观看连接 | R1 | 引入“观看者计数”（WS 连接 + RTC 会话 + HLS 客户端）：为 0 则停 screencast 与帧泵；>0 再启。要处理新连接首帧（`last_frame` 回放或强制出帧） |
| G2 | 非前台 tab 的画面采集与声音的关系未理清（**待核实**：Chromium 后台标签是否继续往 pulse 出声；screencast 只跟随 `view_session`） | R2 | 先实测后台 tab 声音是否持续；设计“仅音频 tab”状态：停该 tab 画面采集，保留声音 |
| G3 | 局部变化仍整页重采 | R1/R3 | 用变化日志的 `Nodes` 只重算变化节点（`element_core` 已共用），合并进存储帧并出增量；**先量“变了一块”时整页重采的真实代价再决定** |
| G4 | 两套变化来源：DOM 镜像用页内 MutationObserver，AI 用 CDP 事件 | R1（“AI 与画面一样”） | 评估统一成一份“变化记录”（谁订阅谁取）；注意页内观察者能看到更多（属性/文本粒度），CDP 事件只到节点级 |
| G5 | 视频模式/screencast 本身不是“只传变化项” | R1 | screencast 已按帧变化产出（静态页无新帧）；进一步需评估内容帧（子区域）与脏矩形传输；RTC 路已有编码层的帧间压缩 |
| G6 | 后台 DOM 感知常驻（模式自适应为此常驻 `dom-start`） | R1 | 评估用轻量页面摘要（视频/canvas/交互元素的面积统计）取代完整 DOM 镜像做模式裁决 |
| G7 | 观看状态散落（显示偏好/生效画面源/DOM 订阅/音频需求）靠轮询与超时收敛；视口只记“已送出”，无“已套用”回报 | R3 | GPT 审查 P2 与“底层统一”第 1、2 条：边缘按连接管理观看状态，统一转移规则；增加视口已套用回报 |
| G8 | `observe` 的 `subtree/budget` 仍全量采集 | R1 | 视 G3 结果决定是否按需采集 |
| G9 | 局部复核未覆盖子帧；`since_frame` 命中后对“权威性”的约定需写进调用方文档 | R4 | 子帧加帧偏移后纳入快速复核 |

## 8. 本轮（2026-11-21）改动点（提交 `d9f7361`，已合入本地 `main`）

**P1 修复**
- `main.rs`：WS JPEG 帧是否发送只看观看端 `jpeg-demand`（`jpeg_want`），删除 `dom_active`；后台 DOM 订阅不再停帧。
- `ai.rs`：截图遮罩取自完整快照（`draw_marks(png, view, full)`）；采集期间换页 → 丢弃截图只留警告。

**操作与呈现解耦（含 `rig-proto` 契约变化）**
- `ActionResult::Done.frame_id` = 动作所基于的校验帧（旧：动作后新帧）。`act` 不再动作后整页刷新。
- 新增 `changes.rs` 变化日志 + `Cdp::tap` 同步钩子；`observe(since_frame)` 无变化→空增量、不采集（`/health` 的 `changes.observe_unchanged`）。
- 被拒时附最新状态（`act_with_fresh`）：delta 或整帧；<500ms 的帧复用。
- 动作前**单元素快速复核**（`fast_confirm`，`element_core` 抽出共用）；`/health` 的 `act_precheck.fast_hit/fast_miss`。
- `Browser` 新增 `ax_node`（`getPartialAXTree`）、`dom_attrs`（`describeNode`）、`view_state`（`getLayoutMetrics`）。

**人通道效率**
- `LazyRgb`：帧泵只存原始 JPEG，RTC/HLS/V02 取用时才解码（无视频订阅时解码 869→0 次/15s）。

**测试**
- 新增：`lazy_rgb_decodes_once_and_normalizes`、`draw_marks_masks_sensitive_from_full_not_trimmed_view`、`rejected_stale_attaches_fresh_state`、
  `observe_since_returns_empty_delta_when_unchanged`、`act_done_does_not_refresh_and_points_at_validated_frame`、`changes` 6 项；
  集成 `edge_dom_subscription_keeps_jpeg_frames`、`edge_act_fast_precheck`、`edge_observe_unchanged_vs_changed`。
- 全量：单元 58、集成 18（含 AV）、eval 11、proto 31，`clippy -D warnings` 无警告。

**实测数据（debug、本地回环、n=20、页面无副作用）**

| 场景 | 改前 | 单元素复核后 | 解耦后 |
|---|---|---|---|
| 小页点击 `act` p50 | 130.0 ms | 101.1 ms | **65.9 ms** |
| 大页（~550 元素）点击 `act` p50 | 未测 | 246.2 ms | **67.8 ms** |

**页面确有变化时 `observe(since)` 的耗时未测。**

## 9. 本机开发/测试环境要点

- 集成测试：`RIG_EDGE_IT=1 cargo test`（需真 Chromium；`RIG_CHROMIUM` 可指定，否则扫 `~/.cache/ms-playwright`）。
- AV 测试额外需要：便携 PulseAudio（`.temp/pulseaudio`，按 `scripts/edge-lan.sh` 启动并导出 `PULSE_SERVER` 等）+ `ffprobe`（`apt-get install -y ffmpeg`）。
  **坑**：`edge-lan.sh` 的环境会改 `HOME`，跑测试前在 source 后再 `export HOME=/root`，否则找不到 Chromium、git 报 dubious ownership。
- 不要用 `pkill -f`/`pgrep -f` 清进程（模式串会匹配到执行它的 shell 自己，退出码 144）；用 `ss -ltnp` 取 PID 精确 kill。
- 临时产物放 `.temp/`（不是 `temp/`）；基准脚本在会话 scratchpad 里，**不在仓库**（需要的话应整理进 `scripts/` 或 `eval/`）。
- 实测数字都要注明环境；debug 与 release 差距大，局域网脚本默认优先 release。
