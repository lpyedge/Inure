# 05 编译、部署与运行

> 依赖见 [04](04-依赖与环境.md)。构建和测试命令在仓库根目录执行，部署配方从发布包的解压目录执行。

## 发布包目录

| 路径 | 用途 |
|---|---|
| `rig-edge-browser`（Windows 为 `rig-edge-browser.exe`） | 启动器，处理依赖安装和服务启动 |
| `engine/rig-edge-browser-core[.exe]` | 核心程序，由启动器加载 |
| `release.json` | 原生目标、媒体 ABI 和默认依赖下载地址 |
| `runtime/lib/`、Linux 的 `runtime/pulseaudio/` | Full 随包附带。Slim 通过 `--install-deps` 安装 |
| `chromium/` | 可选便携浏览器，由 `--install-deps --with-chromium` 安装，也可手动放入 |

## 1. 编译

### 1.1 开发构建与门禁

```bash
source scripts/local-env.sh          # 可选：把构建缓存重定向到 .temp/target，保持仓库干净
cargo build                          # debug 构建
cargo fmt --all --check
cargo clippy --all-targets -- -D warnings
scripts/test.sh unit                 # 单元测试，跳过真实 Chromium
python3 -m unittest discover -s tests/eval_report -p 'test_*.py' -v
```

提交前的完整门禁按顺序运行 fmt、clippy，再运行 `scripts/test.sh all`（含真 Chromium 集成测试）：

```bash
bash scripts/local-gate.sh           # 音视频集成测试还需要 PulseAudio、ffprobe、ffmpeg
```

### 1.2 构建发布包

```bash
source scripts/local-env.sh    # 可选，将构建缓存放在 .temp/target/
scripts/release.sh              # 初次自动下载媒体包，产物在 dist/
```

原生发布工作流生成五个目标的 full/slim ZIP：`linux-x86_64`、`linux-arm64`、`windows-x64`、`windows-arm64`、`macos-arm64`。包名为 `rig-edge-browser-<version>-<git>-<target>-{full,slim}.zip`，并有 `.sha256` 文件；每个 target/媒体 ABI 另有依赖索引 JSON。Linux 构建从 Ubuntu 官方 APT 仓库准备或重用 `.temp/media-deps/` 的 FFmpeg 与 PulseAudio；桌面构建使用 vcpkg 的 FFmpeg。Linux CI 在 Ubuntu 24.04 x86_64 与 ARM64 runner 构建，glibc 基线为 2.39，不承诺支持所有 Linux 环境。更多平台限制见 [04 §2](04-依赖与环境.md#2-已验证环境)。日常使用系统库的开发构建可通过 `scripts/build.sh` 完成。

**用 release 构建做真实使用与性能判断**：debug 构建下 DOM 序列化、JPEG 编码、合成慢一个量级（实测 DOM 模式明显卡顿），本项目历史上的延迟数字都标注为 debug 构建。源码开发与发布构建使用仓库脚本；消费者使用原生 ZIP，不直接部署开发目录中的二进制。

观看页资源已嵌入核心程序。Full ZIP 附媒体运行库，Linux 还带 PulseAudio。Slim ZIP 可通过 `--install-deps` 补齐运行库。Windows/macOS 提供无系统音轨的观看模式。普通启动照常运行服务。只在执行 `--install-deps` 初装或更新时下载运行库。

### 1.3 常用脚本一览（`scripts/`）

| 脚本 | 用途 | 例 |
|---|---|---|
| `build.sh [debug\|release]` | Linux 开发构建并用 `ldd` 检查动态库，默认 release | `scripts/build.sh` |
| `test.sh [unit\|it\|av\|py\|all]` | `unit` 跳过真 Chromium；`it` 跑 Chromium 集成测试；`av` 只跑音视频用例；`py` 跑 Python 自测；`all` 一次跑完全部测试 | `scripts/test.sh it` |
| `local-gate.sh` | **提交前完整门禁**：fmt → clippy → `scripts/test.sh all` | `bash scripts/local-gate.sh` |
| `prepare-media.sh` | 下载并解包 Ubuntu 官方 FFmpeg 和 PulseAudio 软件包 | `scripts/prepare-media.sh` |
| `release.sh` | 原生编译并生成 full/slim ZIP、SHA-256 与依赖索引 | `scripts/release.sh` |
| `docker-release.sh <release-prefix>` | 从 Linux ZIP 构建本地 Docker 镜像，参数见 §4.3 | `scripts/docker-release.sh --help` |
| `run.sh [边缘参数…]` | 本地快速运行：随机令牌（或 `RIG_EDGE_TOKEN`）+ 观看页；在 `CARGO_TARGET_DIR`（或默认 `target/`）下的 release/debug 候选中选择最新可执行文件 | `PORT=40000 scripts/run.sh --url https://example.com` |
| `edge-lan.sh [边缘参数…]` | Linux 局域网 HTTPS 测试，使用 `ip`、`ss` 和 `curl`，等待新实例的 `/ready` | `PORT=39871 scripts/edge-lan.sh` |
| `clean-tmp.sh [--yes]` | Linux 临时目录清理，默认只列出，`--yes` 才删除 | `scripts/clean-tmp.sh` |
| `local-env.sh` | `source` 它把构建缓存重定向到 `.temp/target`（可选） | `source scripts/local-env.sh` |
| `eval_report.py` | 评估 `RunRecord` 汇总（不自动下结论） | 见 [09](09-测试与评估.md) |

## 2. 命令行参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--listen <addr:port>` | `127.0.0.1:39871` | HTTP 服务绑定地址；`--stdio` 时仅 `--human` 才用于观看页 |
| `--url <url>` | `about:blank` | 启动后导航的页面；其 origin 自动进入导航白名单 |
| `--allow-origin <origin>` | — | 追加允许 `navigate` 的 origin，可重复 |
| `--width` / `--height` | 1280 / 800 | 视口尺寸 |
| `--chromium-dir <path>` | 自动发现 | 自拉起模式最后回退使用的 Chromium 目录。发布包先查包旁 `chromium/`，再查 PATH 与平台默认位置；源码直接运行从 PATH 和平台位置开始。支持平台对应文件名及 macOS 应用包；不探测 Playwright 缓存 |
| `--pulseaudio-dir <path>` | 启动器提供 | 指定便携 PulseAudio 解包目录。未指定时启动器可传入随包目录；源码运行若未指定则尝试从 `PATH` 启动 PulseAudio |
| `--cdp-url <base>` | — | **挂靠模式**：连接已有 Chromium 的 DevTools HTTP 基地址；边缘退出只断开 |
| `--profile-dir <path>` | 临时目录 | 持久化目录：Chromium 用户数据（登录态、Cookie、存储、扩展） |
| `--cache-dir <path>` | profile 内 | 可弃缓存目录；其下 `uploads/` 是 `upload` 动作的唯一允许根目录 |
| `--token <secret>` | `RIG_EDGE_TOKEN` | **对外提供 HTTP 时必设**，空值视同未设。由启动程序随机生成并传入 |
| `--human` | 关 | 显式给出时人通道默认开启 |
| `--no-ai` | AI 开启 | 启动时关闭 AI 通道 |
| `--av` | 关 | 允许 HLS 播放；首个有效播放列表请求才启动合流管线 |
| `--stdio` | — | 以 MCP stdio 作 AI 通道前端 |
| `--embed-origin <o[,o…]>` | — | 允许内嵌观看页的宿主来源；未给则**禁止任何内嵌** |
| `--tls-cert` / `--tls-key` | — | HTTPS；须成对给；文件缺失时自动生成自签名证书（0600 落盘复用） |
| `--stun <host:port>` | — | 可重复。配了则 RTC 走完整 ICE 并采集 srflx 候选（跨子网直连）；不配走 ICE-lite + host 候选 |
| `--install-deps [--with-chromium] [--deps-base-url HTTPS_URL]` | — | **发布启动器单独命令**：安装或更新匹配的媒体运行库；可选安装便携 Chromium 或指定托管资源目录。不能与普通浏览器参数组合 |

**强制规则**

- 提供 HTTP（默认模式或 `--stdio --human`）时须通过 `RIG_EDGE_TOKEN` 或 `--token` 传入随机令牌。缺少令牌时退出码为 2。
- **非回环监听强制 TLS**：没给证书就自动生成自签名到 `~/.rig-edge/self-signed.{crt,key}`，SAN 含监听 IP、`127.0.0.1`、`localhost`。
- 回环监听不强制 TLS（localhost 本身是安全上下文，剪贴板 API 可用）。
- 纯 `--stdio` 通过进程管道通信，令牌可省略。

## 3. 运行配方

发布包的启动入口会加载随包媒体运行库；Linux 包还会把 PulseAudio 目录传给程序。自行指定 `--pulseaudio-dir` 时，该参数优先。目录无效时会在 stderr 报告原因，视频仍可无声播放。

```bash
BIN=./rig-edge-browser
TOKEN=$(head -c 16 /dev/urandom | od -An -tx1 | tr -d ' \n')
```

在源码仓库里运行时，可改用 `BIN="${CARGO_TARGET_DIR:-target}/release/rig-edge-browser"`。

### 3.1 人在本机看（观看页）

```bash
RIG_EDGE_TOKEN="$TOKEN" "$BIN" --listen 127.0.0.1:39871 --human --url https://example.com
```

浏览器打开 `http://127.0.0.1:39871/`，在输入页填令牌进入。

### 3.2 AI 本机子进程（MCP stdio）

```bash
"$BIN" --stdio --url https://example.com            # 只有 AI，无 HTTP
RIG_EDGE_TOKEN="$TOKEN" "$BIN" --stdio --human --listen 127.0.0.1:39871 --url https://example.com
#                     ↑ 同时给人开观看页（只挂 Viewer 路由，AI 仍只走 MCP）
```

宿主把它当子进程拉起，stdin/stdout 走 JSON-RPC；诊断输出走 stderr。stdin 关闭即正常退出。接入配置见 [07](07-智能体接入方案.md)。

### 3.3 局域网（HTTPS + 令牌）

```bash
# 将 LAN_IP 设为对端访问时使用的本机 IPv4 地址
RIG_EDGE_TOKEN="$TOKEN" "$BIN" --listen "${LAN_IP}:39871" --human --url https://example.com
# 在客户端信任边缘证书。EDGE_CA 指向自签名证书或签发它的 CA 证书。
curl -sS --cacert "$EDGE_CA" -X POST "https://${LAN_IP}:39871/observe" -H "Authorization: Bearer $TOKEN" \
     -H 'content-type: application/json' -d '{"mode":"text"}'
```

源码开发可用 `PORT=39871 scripts/edge-lan.sh` 启动。两个启动脚本都通过 `PORT` 和 `RIG_EDGE_TOKEN` 配置监听端口与令牌，支持转发 `--chromium-dir`、`--pulseaudio-dir`。LAN 脚本等待 `/ready`；MCP 宿主应直接调用发布入口。

### 3.4 挂靠已有的 Chromium

```bash
PROFILE="$(mktemp -d)"
chromium --remote-debugging-address=127.0.0.1 --remote-debugging-port=9222 \
  --user-data-dir="$PROFILE" &
"$BIN" --cdp-url http://127.0.0.1:9222 --stdio
```

边缘退出时**不会**关闭你的浏览器。挂靠模式下快照只收录当前授权的标签页。

### 3.5 持久化登录态

```bash
RIG_EDGE_TOKEN="$TOKEN" "$BIN" --listen 127.0.0.1:39871 --human \
     --profile-dir /var/lib/rig/profile --cache-dir /var/cache/rig
```

同一 profile 可跨重启保留登录态。迁移前先用 SIGTERM 停机，并备份整个 `--profile-dir`（见 §5）。

### 3.6 音视频（HLS 兜底 + 声音）

用 `--human --av` 启用音视频观看。边缘自动发现 PulseAudio 并创建独立的 `rigsink`；缺少 PulseAudio 时提供无声视频。视频主路是 WebRTC，HLS 可用于回落。

### 3.7 内嵌进智能体 Web UI

```bash
RIG_EDGE_TOKEN="$TOKEN" "$BIN" --listen "${LAN_IP}:39871" --human --embed-origin https://agent.example.com
```

宿主页面嵌 `<iframe src="https://<edge>:39871/">`，用 `postMessage` 自动授权。协议见 [06 §内嵌](06-接口与调用.md)。

## 4. 部署

### 4.1 部署清单

1. 解压对应原生 target 的 ZIP，保留目录结构。Full 已含运行库；Slim 先在解压目录执行 `./rig-edge-browser --install-deps`。
2. 准备 Chromium。可运行 `--install-deps --with-chromium` 安装到启动器旁，也可使用系统浏览器或用 `--chromium-dir` 指定最后回退目录。 [Chromium 查找顺序](04-依赖与环境.md#33-chromium-发现方式)
3. 规划目录：`--profile-dir`（要备份）、`--cache-dir`（可弃）。
4. **由启动程序**（systemd、容器入口、宿主进程）在每次启动时生成随机令牌并传入。
5. 局域网部署放通 **TCP 监听端口**；WebRTC 用 UDP（端口为系统临时端口，绑在监听 IP 上）。**UDP 不通时画面自动回落 WS JPEG/HLS**，功能不丢，只是带宽与流畅度差一些。
6. 反向代理（如 nginx）：需透传 WebSocket；注意 `Authorization` 头与 `/stream/` 路径必须原样转发。

### 4.2 systemd 单元示例

> **未在本仓库验证**，仅供参考；路径、用户按实际调整。

```ini
[Unit]
Description=rig-edge-browser
After=network.target

[Service]
User=rig
# 由部署工具在启动前写入 RIG_EDGE_TOKEN=<随机值>，文件权限为 0600
EnvironmentFile=/run/rig/token.env
ExecStart=/opt/rig/rig-edge-browser --listen 0.0.0.0:39871 --human \
          --profile-dir /var/lib/rig/profile --cache-dir /var/cache/rig
# 必须用 TERM 优雅停机，让 Chromium 把 Cookie/LocalStorage 落盘
KillSignal=SIGTERM
TimeoutStopSec=20
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

### 4.3 容器注意

- `scripts/docker-release.sh <release-prefix> [host-label ...] [--variant full|slim]` 从 Linux ZIP 构建 Debian 13 Linux 工作负载，不会构建或运行原生 Windows/macOS 容器。例如：`scripts/docker-release.sh dist/rig-edge-browser-1.2.3-abcd-`。脚本默认处理五个 host label 和 full/slim；标签映射到 linux/amd64 或 linux/arm64，去重后实际构建四种镜像变体，再创建十个 host-label 标签。它使用 `buildx --load`，不会推送镜像。
- Dockerfile 在 Debian 13 中安装系统 Chromium 与 CA 证书；容器内浏览器来自系统安装。Full 镜像在 `/opt/rig` 带完整运行库。Slim 镜像可挂载持久化命名卷到 `/opt/rig`，首次以 `--install-deps` 填充/更新媒体运行库：

  ```bash
  docker volume create rig-data
  docker run -v rig-data:/opt/rig rig-edge-browser:1.2.3-abcd-linux-x86_64-slim --install-deps
  TOKEN=$(head -c 16 /dev/urandom | od -An -tx1 | tr -d ' \n')
  docker run -v rig-data:/opt/rig -p 127.0.0.1:39871:39871 \
    -e RIG_EDGE_TOKEN="$TOKEN" rig-edge-browser:1.2.3-abcd-linux-x86_64-slim
  ```

  宿主通过 `https://127.0.0.1:39871/` 打开观看页，首次使用容器内的自签名证书时需先信任它。自建发布需提供匹配的依赖索引和 ZIP，可在构建时设 `RIG_RELEASE_BASE_URL`，也可在安装时传 `--deps-base-url`。
- 容器内以 root 运行时边缘会自动给 Chromium 加 `--no-sandbox`；非 root 则保留沙箱，容器需要相应能力或用户命名空间。
- Chromium 需要足够的共享内存（`/dev/shm`），否则页面会随机崩溃。
- Linux 发布 ZIP 带有 PulseAudio 运行库，边缘会创建并清理虚拟声卡。

## 5. 运维

### 5.1 健康检查

| 端点 | 用途 |
|---|---|
| `GET /ready` | CDP/session 健康探针：CDP 存活且至少有一个页面会话 → 200，否则 503。免鉴权；不代表音视频或观看页就绪 |
| `GET /health` | 存活与可观测：`ok`、`ready`、`cdp_connected`、`last_frame_age_ms`、`exec_in_flight`、`rtc_connected`、`frames`、各阶段延迟分位（`latency`）、`last_snapshot`、`act_precheck`（快速复核命中/退回）、`changes`、`media` 等。免鉴权 |

### 5.2 停机与升级

- **用 SIGTERM（或 Ctrl+C）停机**：边缘先 `Browser.close` 让 Chromium 落盘，再删除本进程的临时目录。SIGKILL 会丢最近几秒的 Cookie/LocalStorage 写入，并留下 `/tmp/rig-edge-*` 残余。
- 升级时用 SIGTERM 停机，在新目录解压完整发布包。Slim 先执行 `--install-deps`，再用新版启动器和原有持久化目录启动。
- **换令牌**：换一个值重启即可；所有 `access`/`refresh` 票据随进程重启全部失效，观看页会回到令牌输入页。

### 5.3 日志

诊断输出全部走 **stderr**（MCP 模式下 stdout 只写协议帧，不得污染）。启动时会打印 `profile=… cache=…` 与 `uploads=<路径>`。日志中不应出现令牌或输入内容。

### 5.4 清理残留

Linux 上可用 `clean-tmp.sh` 检查 `${TMPDIR:-/tmp}` 中当前用户拥有的残留目录。脚本通过 `/proc` 跳过仍在运行的进程及符号链接，默认只列出，加 `--yes` 才删除。识别 `rig-edge-<pid>`、`rig-edge-<pid>-uploads`、`rig-edge-hls-<pid>` 和 `rig-edge-<pid>-pulse`：

```bash
scripts/clean-tmp.sh
scripts/clean-tmp.sh --yes
```

## 6. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 启动即退出，退出码 2 | 对外提供 HTTP 但没给 `--token`（或为空）。生成随机令牌并传入 |
| 启动报找不到 Chromium | 确认系统 Chromium 在 `PATH`；或用 `--chromium-dir /path/to/chrome-linux64` 指定含 `chrome` 的目录 |
| Linux 没有声音但画面正常 | 确认 `/channels` 的 `audio_available`。为 false 时检查发布包的 `runtime/pulseaudio/` 或启动诊断。见 [04 §4.2](04-依赖与环境.md) |
| 局域网观看页打不开 / 证书警告 | 自签名证书，浏览器要先信任一次；iframe 内嵌时同样 |
| 观看页能进但剪贴板不工作 | 用 `http://` 经局域网 IP 访问是非安全上下文。改用 HTTPS（局域网默认就是）或 `localhost` |
| 画面一直黑 / 很卡 | 先看是不是 debug 构建；再看 UDP 是否被防火墙拦（回落到 JPEG 流会卡）；`/health` 看 `rtc_connected` |
| `act` 被拒绝 `stale_frame` | 页面在 `observe` 之后变了。重新 `observe` 再操作（拒绝回包里已附最新状态） |
| `act` 返回 `aborted` | 用户强制接管，或 AI 通道被关闭过。停下原任务，等用户新指示，`observe` 后再继续 |
| `Type` 被拒（`policy_denied`，详情 “The Type target did not receive focus after the click…”） | 点击目标不是可聚焦元素，或页面重设了焦点。换目标元素 |
| `upload` 被拒 `policy_denied` | 文件不在上传目录内。放进 `<cache-dir>/uploads/`（启动日志里有 `uploads=`） |
| 改了 `viewer.js` 没生效 | 它是 `include_str!` 嵌入的，需要重新编译二进制 |
| 在同一 shell 里测试找不到 Chromium | 用 `RIG_EDGE_TEST_CHROMIUM_DIR=/path/to/chrome-linux64` 指定直接含 `chrome` 或 `chromium` 的测试目录；默认也查 `PATH`，不依赖 `HOME` |
