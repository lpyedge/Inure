# 10 路线图与已知局限

## 1. 后续优化的验收标准（用户需求，R1–R5）

> 以下是用户（LIU）2026-11-21 明确提出的方向，是**后续优化的验收标准**。

| # | 需求 | 含义 |
|---|---|---|
| **R1** | **不观察不传送，只传最小变化** | 没有连接人通道或 AI 通道，就不做对应的数据采集；连接后以**当前标签**采集，尽量只传输**具体变化内容**。**AI 通道和画面通道一样处理；DOM 模式和视频模式同样处理。** |
| **R2** | **声音是特例** | 有声音的标签允许继续以**非前台方式**发声音，但它的**画面可以被忽略**（不采集不传送） |
| **R3** | **操作与呈现是两个逻辑** | 操作只回答「有没有执行」；呈现由变化检测驱动、按变化量送出（没变就不送，局部变就送局部，换页才送整页）。人工与 AI 的所有操作交互是同一个逻辑 |
| **R4** | **程序负责保险，不要求使用者迁就** | AI 要求操作某元素而它已不可交互/不在原位，**程序**返回失败 + 具体原因，同时送出**最新状态**让 AI 继续；不是让 AI 自己想办法多要数据 |
| **R5** | **允许调整 AI 通道数据 schema** | 目标：和实际页面对应、数据合理且不大、**保持局部刷新能力**。审查结论：元素 id 已绑定真实节点且跨帧稳定，公开 schema 基本不用改 |

## 4. 已知局限（现状如实）

**能力边界**

- 被控目标为 **Chromium**。已验证的平台及原生发布目标见 [04 依赖与环境](04-依赖与环境.md)。
- 人通道提供 JPEG、WebRTC、HLS 和 DOM 镜像。无语义页面可用截图与坐标操作。
- 人通道不做文件粘贴（观看端读不到使用者本机文件）。
- 浏览器内部页（`chrome://` 设置/下载/扩展等）**仅视频模式**：WebUI 全在 shadow DOM 里，镜像拿到的是空壳。
- DOM 模式：同源 iframe 内容整棵镜像；跨源 iframe 与 `<video>` 走区域子流（可看可点，但内部滚动不同步、内部 DOM 不镜像）；canvas：单边 >1024px 的大画布（游戏画面）走**区域子流**（边缘按 rect 截图，约 4fps，WebGL 也能显示）；≤1024px 的小画布仍走快照式子流，其中 WebGL 读不出像素、跨源污染的画布只留占位；页面自身 JS 不在镜像里执行。
- 右键菜单是观看端自绘（原生菜单是浏览器 UI 层，不在截帧里）。
- 非安全上下文（经局域网 HTTP）下 Async Clipboard API 不可用，文字复制降级为手动复制框，图片回拷不可用。正道是 HTTPS（局域网默认就是）。

**感知与动作**

- 纯视觉变化无通知：滚动（已另读视口补上）、CSS 动画、`:hover` 显隐不产生 DOM 事件；「没通知」≠「页面没变」。
- 局部变化仍整页重采；子帧（OOPIF）元素不走快速复核。
- 增量观察的基帧池只留最近 8 帧；基帧更旧的 `since_frame` 回完整视图。动作校验同样只认最近 8 个已交付的帧：更旧的 `frame_id` 一律判陈旧。
- 批量动作里每一步都对同一个 `frame_id` 校验：同一批里重复点会改变布局的同一控件（日历“下个月”、会重排的分页）时，后面的步骤会因目标移动被拒，应拆成单独调用；前一步让后一步的目标从禁用变可用（取消勾选后输入框启用）则放行。
- `select` 只作用于原生 `<select>`；自定义下拉要点开、输入、点选项（`layout=blocks` 会把展开的 listbox 选项连同 id 列出来）。
- 跨进程 iframe 的子会话若无法定位，其元素不会出现在观察里，而不是以错位坐标出现：宿主 iframe 找得到但没有几何（`display:none`、零尺寸，广告和追踪器常见）时静默跳过；连宿主都找不到（层级没传播完整）才附告警，因为告警会让截图被拒、文本差分失效；宿主在另一个同样没定位的隐藏会话里（隐藏广告再嵌别的跨站 iframe）也算找到。**已知局限**：“没有几何”也可能是几何查询真的失败了（宿主节点在 DOM 映射和几何调用之间被重渲染），此时可见的内容会静默缺失而没有告警；坐标不会错，只是 AI 得不到“缺内容”的信号。
- `observe` 的 `subtree`/`budget_tokens` 仍是全量采集后裁剪（只省 token，不省采集）。
- AI 通道只操作**人当前活动标签**；人切换标签后，旧帧元素校验必然拒绝，属预期行为，AI 应重新 observe。
- 人通道视频帧与 AI 的 Observation 帧是两条管线，**没有共同帧号**；关联性靠 observe 采集前后的主文档 `loaderId` 代次校验。

**站点侧限制（非边缘缺陷）**

- YouTube、Bilibili 等对数据中心出口 IP + 自动化浏览器有机器人门槛：播放器不创建或不加载媒体。出路在部署/账号层（观看端登录账号、换住宅出口），边缘代码无可修。「播不了」先查站点对出口的处置，再疑边缘。
- 指纹残留（已知、未处理）：WebGL renderer 字符串含 SwiftShader（VM/远程桌面同款）；DOM 模式用过的页面留 `__rigDom`/`__rigSend` 全局；出口 IP 地理与人格时区不一致属部署层。

**其他**

- RTC 唇音同步残差：已按共享纪元对齐，残差为两侧管线延迟差（约几十 ms），未做采样级实测校准。
- 并发说明：按**单人受信工具**设计。多观看端并发时 `/channels` 等全局状态不保证相互独立；未来多用户再引入连接级策略。
- 临时目录在 SIGKILL/崩溃时无法清理。

## 4.1 代码评审（2026-11-24，GPT 静态评审）处置

评审报告 `plan/chromium-client-review-report.md` 是静态源码审查（无 `cargo`、无 Chromium 复现，**不是独立验收**）。逐条对照源码核实后的处置：

| 条目 | 结论 | 处置 |
|---|---|---|
| F01 深层 OOPIF 偏移最多传 4 轮 | **属实并复现**：10 层嵌套时旧代码约 4/10 次把最深按钮报在错误坐标 | 已修：传播轮数按会话数，未定位会话不输出元素并告警；回归 `edge_deeply_nested_oopif_coordinates_are_global` |
| F02 帧泵异常停止后不重启 | 属实（控制流确认） | 已修：运行中每秒检查，启动失败指数退避（500ms 起、30s 封顶）；管理循环与浏览器解耦（启动、善后由调用方注入），**故障注入测试**用假泵任务（80ms 后自行退出）和两次注入的启动失败，验证需求不变时自动重启、退避重试、撤销需求后停止；**变异检查**（把“有泵时定期醒来”改回修复前的行为）该测试失败。**整条链路的崩溃注入在当前设计下做不了**：泵任务只在 CDP 广播通道关闭（浏览器连接断开）时才退出，连接还活着时外部无法让它退出（渲染进程崩溃后重载泵照样恢复，区分不了修复前后），所以不作为证据 |
| F03 删除同源 iframe 后监视器残留 | **属实并复现**：增删 30 个后残留 30 个 | 已修：`dropSubtree` 解除，嵌套的同源 iframe 递归解除，另在每次整页重同步时清扫“iframe 元素已不在文档里”的监视器（覆盖在被监视的 iframe 内部增删 iframe 的情况）；回归 `edge_dom_mirror_releases_watchers_of_removed_iframes`（含嵌套与内部增删，仅修第一版时嵌套场景残留 14 个） |
| F04 HLS 停机超时后与下次启动共用目录 | 条件性（需合流线程阻塞 >10s），未复现 | 已按评审的最小修法改：每次管线独立代次目录，线程没退出不删目录；重启换新代次目录由 F05 的注入测试覆盖；**停机超时注入**：`join_then_cleanup` 抽成可测函数，卡住的线程（忽略停止信号）超时后目录原样保留、按时退出的线程目录被清掉，变异检查（超时也删目录）该测试失败 |
| F05 HLS 写包错误被忽略 | 属实（`let _ =`） | 已修：10 秒窗口内累计 3 次写包错误放弃管线（并置停止标志，否则带音频时会卡在回收音频线程上，要等 12 秒空闲回收才“停”，这是独立评审发现的），经 `/health` 报告原因，下一次请求用新目录重启；**故障注入（运行中删除输出目录）实测通过**，并因此把最初的“连续 30 次”判据改成了滑动窗口 |
| F06 元素 id 映射只按会话回收 | 属实（增长速度未量测） | 已修：按采集轮次打戳，节点连续 8 轮没出现才回收；id 只增不复用，旧 id 的动作照旧被拒；单元测试覆盖；**内存斜率实测**（页面每 250ms 换 300 个新节点，400 次观察，debug 构建）：修复前 RSS 104→143 MB，修复后稳定约 99 MB（`eval/bench/probe_rss_churn.py`） |
| F07 refresh token 数量无上限 | 属实 | 已修：同时有效最多 32 张，超出时最早签发的作废；不改“无时限、用一次轮换一次”的机制（[08](08-安全模型.md)） |
| F08 DOM 镜像只遮蔽 `type=password` | 属实（已知安全欠账） | 已修：镜像与 AI 通道同一判定口径，补银行卡与验证码字段；敏感下拉框的已选中状态（`k:1`、`selected` 属性）同样不进镜像；仍基于页面标注，**未标注的字段两条通道都认不出**（经用户确认不加名字启发式） |
| O01 局部观察仍整页采集 | 评审要求先量测。**实测**（debug 构建、本机、同一份 `/health.last_snapshot`，每页 25 次观察）：向导步骤 1（92 节点）总计约 13 ms、8 次 CDP；45 行报销表（375 节点）约 31 ms、8 次 CDP；未打开工单的工单台（85 节点）约 10 ms；80 行订单表 + iframe（1633 节点）约 138 ms、30 次 CDP，其中 AX + DOM 采集约 114 ms，几何（quads）仅约 8 ms。代价基本随节点数线性增长（约 0.085 ms/节点），小页面都在十几毫秒量级 | **不做局部重算（G3/G8 维持“按需再评估”）**：只有上千节点的页面才到百毫秒级，而且这是 debug 构建，release 与真实网络未测；局部重算要承担“没通知 ≠ 没变化”的正确性风险，收益只在大页面 |
| O02 HLS 每帧整图复制 | 属实（`crop_even` 同尺寸也 `clone`） | 已修：尺寸匹配时借用（`Cow::Borrowed`），只有奇数边才裁剪复制；单测断言指针相同。每帧省一次整图拷贝（1280×800 RGB24 约 2.9 MiB）。**未量 CPU 收益**，只是去掉确定多余的拷贝 |
| O03 HLS 默认双路编码 | 属实；开关早已有 | **实测**（debug 构建、本机、动画页、1280×800、含 20 秒稳态，边缘进程 CPU，不含 Chromium）：默认双路（HEVC + H.264）约 64.5% 单核，`RIG_HLS_SINGLE=h264` 约 14.1% 单核（各重复一次，结果一致），单路省约 78%，开销主要是 x265。**默认不改**：单路 H.264 会放弃 HEVC 路径，要在已知观看端编解码能力后由部署方决定（[05](05-编译部署与运行.md)） |
| O04 截图脱敏与校验链路 | 评审要求分阶段计时、不得以牺牲安全换速 | **未做**：没有证据显示截图是瓶颈（截图约 400 ms 的旧数据只是量级），按评审口径在有量测依据前不动 |
| O05 批量动作并发语义 | 现有定位是单人受信工具，文档从未承诺整批原子性 | **未改**：架构定版前不改变批量失败语义；评审建议先补并发反例测试，未做 |

## 5. 路线图建议

按「风险 / 价值」排序，**只是建议，不是承诺**：

1. **先补验证欠账**：真实环境目检 `<video>` 出画面与 HLS；浏览器端 refresh 续期的探针；MCP 接管文本块的测试。（成本低、直接降低上线风险）
2. **安全决策**：登录限速要不要做；DOM 镜像敏感字段对齐；服务端只读模式。（需先提方案、等批准）
3. **接入开发**：按 [07 §7](07-智能体接入方案.md) 的验收清单在真实宿主上跑通 Hermes/OpenClaw，度量模型 token。
4. **R1/R3 方向的效率优化**：用 release 构建测量静态页、局部内容变化、重排、iframe 和导航场景的观察延迟、CDP 调用数与响应大小，再评估局部重算与 G4 的变化来源合并。
5. **工程化**：CI 加浏览器 E2E job；探针与基准脚本入库；release 构建与真实网络的性能基线。
