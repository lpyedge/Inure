# 10 路线图与已知局限

## 1. 后续优化的验收标准（用户需求，R1–R5）

> 以下是用户（LIU）2026-11-21 明确提出的方向，是**后续优化的验收标准**。

| # | 需求 | 含义 |
|---|---|---|
| **R1** | **不观察不传送，只传最小变化** | 没有连接人通道或 AI 通道，就不做对应的数据采集；连接后以**当前标签**采集，尽量只传输**具体变化内容**。**AI 通道和画面通道一样处理；DOM 模式和视频模式同样处理。** |
| **R2** | **声音是特例** | 有声音的标签允许继续以**非前台方式**发声音，但它的**画面可以被忽略**（不采集不传送） |
| **R3** | **操作与呈现是两个逻辑** | 操作只回答「有没有执行」；呈现由变化检测驱动、按变化量送出（没变就不送，局部变就送局部，换页才送整页）。人工与 AI 的所有操作交互是同一个逻辑 |
| **R4** | **程序负责保险，不要求使用者迁就** | AI 要求操作某元素而它已不可交互/不在原位，**程序**返回失败 + 具体原因，同时送出**最新状态**让 AI 继续；不是让 AI 自己想办法多要数据 |
| **R5** | **允许调整 AI 通道数据 schema** | 目标：和实际页面对应、数据合理且不大、**保持局部刷新能力**。审查结论：元素 id 已绑定真实节点且跨帧稳定，公开 schema 基本不用改 |

## 2. 现状与需求的差距（G1–G9，按建议优先级）

| # | 差距 | 对应 | 建议 |
|---|---|---|---|
| G1 | 整页采集已按观看需求启停 | R1 | `human.rs::manage_capture` 在无观看者时停止整页帧泵，有需求时恢复。`edge_human_zero_viewers_stops_full_frame_pump` 已覆盖。 |
| G2 | 切换标签后，后台声音持续播放仍待验证 | R2 | 用两个标签验证后台标签持续出声，画面采集保持在当前观看标签 |
| G3 | 局部变化仍整页重采 | R1/R3 | 用变化日志的 `Nodes` 只重算变化节点（`element_core` 已共用），合并进存储帧并出增量；**先量「变了一块」时整页重采的真实代价再决定** |
| G4 | 两套变化来源：DOM 镜像用页内 MutationObserver，AI 用 CDP 事件 | R1 | 评估统一成一份「变化记录」；注意页内观察者能看到更多（属性/文本粒度），CDP 事件只到节点级 |
| G5 | 视频模式/screencast 本身不是「只传变化项」 | R1 | screencast 已按帧变化产出（静态页无新帧）；进一步需评估内容帧（子区域）与脏矩形传输；RTC 路已有编码层帧间压缩 |
| G6 | 自动模式已采用轻量页面摘要 | R1 | 观看端按需发送 `mode-summary` 请求，边缘返回页面摘要供模式选择。 |
| G7 | `/channels` 仍是轮询的共享状态，尚非连接级状态 | R3 | 视口已增加应用确认，RTC 音频轨需求已有连接级处理；剩余 `/channels` 仍通过轮询表达共享通道状态。 |
| G8 | `observe` 的 `subtree`/`budget_tokens` 仍全量采集后裁剪 | R1 | 视 G3 结果决定是否按需采集 |
| G9 | 局部复核未覆盖子帧；`since_frame` 命中后「权威性」的约定需写进调用方文档 | R4 | 子帧加帧偏移后纳入快速复核。**调用方文档部分已在 [06 §6](06-接口与调用.md) 补充** |

## 4. 已知局限（现状如实）

**能力边界**

- 被控目标为 **Chromium**。已验证的平台及原生发布目标见 [04 依赖与环境](04-依赖与环境.md)。
- 人通道提供 JPEG、WebRTC、HLS 和 DOM 镜像。无语义页面可用截图与坐标操作。
- 人通道不做文件粘贴（观看端读不到使用者本机文件）。
- 浏览器内部页（`chrome://` 设置/下载/扩展等）**仅视频模式**：WebUI 全在 shadow DOM 里，镜像拿到的是空壳。
- DOM 模式：同源 iframe 内容整棵镜像；跨源 iframe 与 `<video>` 走区域子流（可看可点，但内部滚动不同步、内部 DOM 不镜像）；canvas：单边 >1024px 的大画布（游戏画面）走**区域子流**（边缘按 rect 截图，约 4fps，WebGL 也能显示）；≤1024px 的小画布仍走快照式子流，其中 WebGL 读不出像素、跨源污染的画布只留占位；页面自身 JS 不在镜像里执行。
- 右键菜单是观看端自绘（原生菜单是浏览器 UI 层，不在截帧里）。
- 非安全上下文（经局域网 HTTP）下 Async Clipboard API 不可用，文字复制降级为手动复制框，图片回拷不可用。正道是 HTTPS（局域网默认就是）。

**感知与动作**

- 纯视觉变化无通知：滚动（已另读视口补上）、CSS 动画、`:hover` 显隐不产生 DOM 事件；「没通知」≠「页面没变」。
- 局部变化仍整页重采；子帧（OOPIF）元素不走快速复核。
- 增量观察的基帧池只留最近 8 帧；基帧更旧的 `since_frame` 回完整视图。动作校验同样只认最近 8 个已交付的帧：更旧的 `frame_id` 一律判陈旧。
- 批量动作里每一步都对同一个 `frame_id` 校验：同一批里重复点会改变布局的同一控件（日历“下个月”、会重排的分页）时，后面的步骤会因目标移动被拒，应拆成单独调用；前一步让后一步的目标从禁用变可用（取消勾选后输入框启用）则放行。
- `layout=blocks` 不渲染展开的 combobox/listbox 的选项，有下拉选项的表单要用默认 `tree`；`select` 只作用于原生 `<select>`，自定义下拉要点开、输入、点选项。
- 跨进程 iframe 的子会话若宿主 iframe 没有几何（隐藏、被拆除、`display:none`）而无法定位，其元素不会出现在观察里（附告警），而不是以错位坐标出现。
- `observe` 的 `subtree`/`budget_tokens` 仍是全量采集后裁剪（只省 token，不省采集）。
- AI 通道只操作**人当前活动标签**；人切换标签后，旧帧元素校验必然拒绝，属预期行为，AI 应重新 observe。
- 人通道视频帧与 AI 的 Observation 帧是两条管线，**没有共同帧号**；关联性靠 observe 采集前后的主文档 `loaderId` 代次校验。

**站点侧限制（非边缘缺陷）**

- YouTube、Bilibili 等对数据中心出口 IP + 自动化浏览器有机器人门槛：播放器不创建或不加载媒体。出路在部署/账号层（观看端登录账号、换住宅出口），边缘代码无可修。「播不了」先查站点对出口的处置，再疑边缘。
- 指纹残留（已知、未处理）：WebGL renderer 字符串含 SwiftShader（VM/远程桌面同款）；DOM 模式用过的页面留 `__rigDom`/`__rigSend` 全局；出口 IP 地理与人格时区不一致属部署层。

**其他**

- RTC 唇音同步残差：已按共享纪元对齐，残差为两侧管线延迟差（约几十 ms），未做采样级实测校准。
- 并发说明：按**单人受信工具**设计。多观看端并发时 `/channels` 等全局状态不保证相互独立；未来多用户再引入连接级策略。
- 临时目录在 SIGKILL/崩溃时无法清理。

## 4.1 代码评审（2026-11-24，GPT 静态评审）处置

评审报告 `plan/chromium-client-review-report.md` 是静态源码审查（无 `cargo`、无 Chromium 复现，**不是独立验收**）。逐条对照源码核实后的处置：

| 条目 | 结论 | 处置 |
|---|---|---|
| F01 深层 OOPIF 偏移最多传 4 轮 | **属实并复现**：10 层嵌套时旧代码约 4/10 次把最深按钮报在错误坐标 | 已修：传播轮数按会话数，未定位会话不输出元素并告警；回归 `edge_deeply_nested_oopif_coordinates_are_global` |
| F02 帧泵异常停止后不重启 | 属实（控制流确认） | 已修：运行中每秒检查，启动失败指数退避（500ms 起、30s 封顶）；仅有退避函数的单测，**故障注入未做** |
| F03 删除同源 iframe 后监视器残留 | **属实并复现**：增删 30 个后残留 30 个 | 已修：`dropSubtree` 解除；回归 `edge_dom_mirror_releases_watchers_of_removed_iframes` |
| F04 HLS 停机超时后与下次启动共用目录 | 条件性（需合流线程阻塞 >10s），未复现 | 已按评审的最小修法改：每次管线独立代次目录，线程没退出不删目录；**未做阻塞注入测试** |
| F05 HLS 写包错误被忽略 | 属实（`let _ =`） | 已修：连续 30 次失败放弃管线，经 `/health` 报告；仅有健康度计数的单测，**磁盘故障注入未做** |
| F06 元素 id 映射只按会话回收 | 未量测增长；回收会碰“并行动作仍在用 id”的边界 | **未改**，需先定 id 生命周期（评审也建议先认可最小方案） |

| O01–O05 性能方向 | 评审自己标为“先量测”；O05（批量并发语义）与现有定位一致 | **未做**；O02（`crop_even` 同尺寸不复制）是低风险微优化，可随时做 |

## 5. 路线图建议

按「风险 / 价值」排序，**只是建议，不是承诺**：

1. **先补验证欠账**：真实环境目检 `<video>` 出画面与 HLS；浏览器端 refresh 续期的探针；MCP 接管文本块的测试。（成本低、直接降低上线风险）
2. **安全决策**：登录限速要不要做；DOM 镜像敏感字段对齐；服务端只读模式。（需先提方案、等批准）
3. **接入开发**：按 [07 §7](07-智能体接入方案.md) 的验收清单在真实宿主上跑通 Hermes/OpenClaw，度量模型 token。
4. **R1/R3 方向的效率优化**：用 release 构建测量静态页、局部内容变化、重排、iframe 和导航场景的观察延迟、CDP 调用数与响应大小，再评估局部重算与 G4 的变化来源合并。
5. **工程化**：CI 加浏览器 E2E job；探针与基准脚本入库；release 构建与真实网络的性能基线。
