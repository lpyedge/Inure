# 04 依赖与环境

面向使用者的发布包按五个原生目标构建：`linux-x86_64`、`linux-arm64`、`windows-x64`、`windows-arm64`、`macos-arm64`。每个 ZIP 名称为 `rig-edge-browser-<version>-<git>-<target>-{full,slim}.zip`，并附 SHA-256 文件；full 附带媒体运行库，Linux 包另带 PulseAudio，slim 只含启动器与核心程序。Slim 可用 `--install-deps` 补齐运行库；full 也可用同一命令更新依赖。包内 `release.json` 记录目标与媒体 ABI。发布平台和边界见 §2。

## 1. 依赖总览

## 2. 已验证环境

当前 Linux x86_64 Full/Slim ZIP 使用 Ubuntu 24.04 构建。实测结果如下。

- Full 在 Ubuntu 24.04 和 Debian 13 容器中通过 FFmpeg 载入与编码器检查。在开发机上用完整解压目录运行，便携 PulseAudio 能采集音轨，HLS 分片含 H.264 与 AAC。
- Slim 通过 HTTPS 完成首次部署和再次更新。校验失败时保留旧依赖。可从官方源安装启动器旁的便携 Chromium。
- 两个 Debian 13 x86_64 Docker 镜像均通过 MCP 初始化，使用系统 Chromium。Slim 的运行库可通过命名卷在容器间复用。

Linux ARM64、Windows x64、Windows ARM64 和 macOS ARM64 配有原生发布任务，尚未在本机验证。以下是历史发布和当前源码开发的环境记录。

| 项 | 版本 |
|---|---|
| OS | Ubuntu 26.04.1 LTS（Linux，`7.0.14-28-pve` 内核，容器/虚拟机环境）；glibc 2.43 |
| Rust | rustc / cargo 1.94.1 |
| FFmpeg 库 | 8.0.1（`libavcodec.so.62`、`libavformat.so.62`、`libswscale.so.9`…） |
| 链接的编码器库 | `libx264.so.165`、`libx265.so.215` |
| Chromium | Playwright `chromium-1248`、系统 Google Chrome 157.0.8103.38 |
| PulseAudio | 17.0（便携解包，见 §4.2） |
| Python / Node | Python 3.14.4；Node 带全局 `WebSocket`（探针用） |
| CI（`.github/workflows/ci.yml`） | `ubuntu-24.04`，`dtolnay/rust-toolchain@stable`；只跑 fmt/clippy/单元测试，**不跑浏览器集成测试** |

原有 Linux x86_64 归档曾由 Ubuntu 26.04（glibc 2.43）构建：主程序要求 `GLIBC_2.39`，随包媒体库要求 `GLIBC_2.43`；该归档在 Ubuntu 24.04（glibc 2.39）和 Debian 13（glibc 2.41）容器中启动失败。当前原生发布工作流改为在 Ubuntu 24.04 的 x86_64 与 ARM64 runner 构建 Linux 包，glibc 基线为 2.39；这不是对所有 Linux 发行版或环境的通用兼容承诺。较旧的 Ubuntu 26.04 构建细节仅适用于上述历史归档。

原生 CI 还构建 Windows x64、Windows ARM64 和 Apple silicon macOS。便携浏览器下载最新稳定 Chrome for Testing；Windows ARM64 没有对应稳定包，改用 Chromium snapshot。Windows/macOS 包不带 PulseAudio 虚拟声卡，视频仍可运行但不会采集系统音轨；macOS 二进位采用 ad-hoc code signing，公证状态**未验证**。

## 3. 源码开发的系统依赖（Debian/Ubuntu）

### 3.1 编译依赖

```bash
sudo apt-get update
sudo apt-get install -y \
  libavcodec-dev libavformat-dev libavutil-dev libswscale-dev \
  libavdevice-dev libswresample-dev \
  pkg-config clang libclang-dev cmake
```

这是 CI 使用的清单（CI 未显式装 `libswresample-dev`，它随其他 `-dev` 包带入；显式列出更稳妥）。Rust 用 rustup：`rustup toolchain install stable --component rustfmt clippy`。

### 3.2 运行依赖

直接用 Cargo 做日常开发时，可使用系统 FFmpeg 共享库，随对应的 `-dev` 包安装。发布构建使用 §4.3 的本地解包目录。可用 `ldd` 核对使用系统库的开发产物：

```bash
ldd rig-edge-browser | grep "not found"     # 应当没有输出
```

Chromium 任选其一：

```bash
# A. 系统包（发行版而异）
sudo apt-get install -y chromium            # 或 chromium-browser
# B. Playwright 管理的 Chromium
npx playwright install chromium
# C. Google Chrome 官方 deb
```

开发机若需要运行音视频集成测试，提供 PulseAudio 测试目录（见 §4.2）；普通消费者无需安装 `pulseaudio`、`pactl` 或 ffmpeg 命令行。

### 3.3 Chromium 发现方式

发布包启动时按顺序查找包旁的 `chromium/`、`PATH` 中的系统浏览器、平台默认安装位置，最后才使用 `--chromium-dir <path>`。源码直接运行没有启动器提供的包内目录，因此从 PATH 和平台默认位置开始，`--chromium-dir` 仍是最后回退。Linux/macOS 识别 `chrome` 或 `chromium`；Windows 识别 `chrome.exe` 或 `chromium.exe`。macOS 也识别 Chrome for Testing、Google Chrome 和 Chromium 的应用包。Windows 默认安装位置包括 Program Files、Program Files (x86) 与 Local AppData 下的 Chrome Application；macOS 查找 `/Applications` 和 `~/Applications`。不会探测 Playwright 缓存目录。

Playwright 的完整 Chromium 可通过绝对路径指定，例如：

```bash
./target/debug/rig-edge-browser --stdio --chromium-dir "$HOME/.cache/ms-playwright/chromium-1248/chrome-linux64"
```

将仓库路径和 Playwright 版本替换成实际位置即可。显式目录仅在更高优先级来源均未找到可执行文件时使用；若指定目录也无效，才会报告 Chromium 缺失。

## 4. 便携放置（不装到系统）

适用于：没有 root、不想动系统包、要把整套环境搬走。

### 4.1 Chromium

可将浏览器目录放在发布入口旁并命名为 `chromium/`，启动器会优先使用它；也可用 `--chromium-dir /path/to/chrome-linux64` 指定浏览器目录。该参数支持直接含可执行文件的目录；macOS 也支持标准 Chrome/Chromium `.app` 布局。Playwright 的完整浏览器目录可整体拷贝。

### 4.1.1 发布包依赖安装与更新

Slim 包启动前需要安装运行库。Full 包可用相同命令刷新运行库；`--with-chromium` 会另外下载与发布目标匹配的便携浏览器到包旁 `chromium/`。在解压目录中单独运行：

```bash
./rig-edge-browser --install-deps
./rig-edge-browser --install-deps --with-chromium
```

安装器通过 HTTPS 获取当前 target 和媒体 ABI 对应的依赖索引，下载 Full 归档并校验 SHA-256。使用本地核心程序检查媒体库后，替换 `runtime/`，并在请求时替换 `chromium/`。停止正在使用该目录的服务后可重复执行此命令，以更新到索引中最新的兼容版本。命令部署完成即退出。普通启动照常运行服务和访问网页，启动时不会下载依赖。CI 构建的包默认指向 GitHub `releases/latest/download`。自建下载位置可在打包时设置 `RIG_RELEASE_BASE_URL`，或通过 `--deps-base-url HTTPS_URL` 指定索引和归档所在目录。

### 4.2 PulseAudio

Linux 发布入口默认使用包内的 `runtime/pulseaudio/`。源码构建可用 `--pulseaudio-dir "$PWD/.temp/media-deps/root"` 使用 §4.3 准备的解包目录，省略参数时从 `PATH` 查找 `pulseaudio`。解包目录含 `usr/bin/pulseaudio`、`usr/lib/<架构>/pulseaudio/`、`usr/lib/pulse-*/modules/`（含 native protocol 与 null sink 模块）及所需共享库。

边缘提供 HTTP 且自拉 Chromium 时（包括 `--stdio --human`），会创建私有 socket 并启动自己的 PulseAudio 进程，由模块创建 `rigsink`。发布包的 PulseAudio 使用隔离的会话总线地址，可与宿主音频服务并存。纯 stdio 与挂靠模式跳过声卡启动。PulseAudio 缺失或启动失败时，观看页仍可使用无声视频。

### 4.3 发布构建的媒体包来源

在 Ubuntu 24.04 amd64 或 arm64 建置机上运行：

```bash
scripts/prepare-media.sh    # 可单独取得原始 .deb，也可直接运行 release.sh
scripts/release.sh
```

`prepare-media.sh` 使用建置机的 Ubuntu 发行版代号和 Ubuntu 官方归档密钥。amd64 使用 Ubuntu Archive 与 Security，arm64 使用 Ubuntu Ports。APT 使用独立工作目录验证签名索引与下载内容，并为 FFmpeg 开发包与 PulseAudio 解析依赖。原始 `.deb` 保留在 `.temp/media-deps/debs/`，解包结果在 `.temp/media-deps/root/`。命令只下载和解包。 [Ubuntu 归档完整性机制](https://documentation.ubuntu.com/security/software-integrity/archive-verification/)

`release.sh` 会先准备或重用这批文件，再使用其中的 FFmpeg 头文件与共享库编译。打包时取同一解包目录内的运行库和 PulseAudio；glibc 和 ELF 加载器由建置机与目标系统提供。需要更新媒体套件时，可先移走可再生的 `.temp/media-deps/`，再重新准备。一般的 Rust、C 编译器、pkg-config、libclang 与 CMake 仍是建置机工具。

Windows 和 macOS 发布构建使用 Microsoft vcpkg 编译 FFmpeg。原生工作流固定 vcpkg 版本，收集所需 DLL 或 dylib，并保留媒体套件许可证。 [原生发布工作流](../.github/workflows/release.yml)

目标机保留发布目录结构。Linux 启动器把 `runtime/lib/` 交给 ELF 加载器，并传入便携 PulseAudio 目录。Chromium 仍需要其运行所需的系统库。

| crate | 用途 |
|---|---|
| `tokio`（full） | 异步运行时 |
| `axum` 0.8（`ws`）、`axum-server` 0.7（`tls-rustls`） | HTTP/WS 服务、TLS |

新增依赖前确认许可证为 MIT / Apache-2.0 / BSD 等宽松许可，并在 PR 里说明理由；AGPL、BSL 项目只读设计，不复制代码（`CLAUDE.md`）。

## 6. 环境变量速查

| 变量 | 作用 |
|---|---|
| `RIG_EDGE_TOKEN` | 同 `--token` |
| `RIG_EDGE_PROFILE_DIR` / `RIG_EDGE_CACHE_DIR` | 同 `--profile-dir` / `--cache-dir` |
| `RIG_EDGE_BUNDLED_CHROMIUM_DIR` | 由可信发布启动器设置为包旁 `chromium/`；独立核心程序通常不设置 |
| `--chromium-dir` | Chromium 的最后回退目录；支持平台对应的可执行文件名及 macOS 应用包 |
| `RIG_RELEASE_BASE_URL` | 发布打包时写入依赖元数据的 HTTPS 资源目录；CI 默认使用 GitHub 最新 release 下载目录 |
| `RIG_CHROMIUM_NO_SANDBOX=1` | 强制禁用 Chromium 沙箱。root 运行时本来就会自动禁用（Chromium 在 root 下无法启用沙箱），其余情况默认保留沙箱 |
| `RIG_EDGE_UA` / `RIG_EDGE_TZ` / `RIG_EDGE_LANG` | 覆盖 UA（整串）、时区（默认 Asia/Tokyo）、语言（默认 ja-JP） |
| `RIG_HLS_SINGLE=h264\|hevc` | 只出一种 HLS 版本（默认双版本） |
| `RIG_PUMP_FULL_ONLY=1` | 帧泵只用整页帧，丢弃内容帧（A/B 与故障回退） |
| `RIG_EDGE_DEBUG` | 打印标签页挂载的调试行 |
| `RIG_EDGE_IT=1` | **仅测试**：启用真 Chromium 集成测试 |
| `--pulseaudio-dir` | 开发时指定 PulseAudio 解包目录，见 §4.2 |
| `CARGO_TARGET_DIR` | `source scripts/local-env.sh` 会重定向到 `.temp/target` |
