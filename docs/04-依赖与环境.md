## 3. 全局安装（Debian/Ubuntu）

### 3.1 编译依赖

```bash
sudo apt-get update
sudo apt-get install -y \
  libavcodec-dev libavformat-dev libavutil-dev libswscale-dev \
  libavdevice-dev libswresample-dev \
  pkg-config clang libclang-dev cmake
```

这是 CI 使用的清单（CI 未显式装 `libswresample-dev`，它随其他 `-dev` 包带入；显式列出更稳妥）。Rust 用 rustup：`rustup toolchain install stable --component rustfmt clippy`。

### 3.2 运行依赖

FFmpeg 共享库随上面的 `-dev` 包带入；只部署不编译的机器装对应的库包即可（包名随发行版的 FFmpeg 主版本变化，如本机是 `libavcodec62`、`libavformat62`、`libavdevice62`、`libswscale9`、`libswresample6`，外加 `libx264`、`libx265` 的运行库）。**用 `ldd` 核对**：

```bash
ldd rig-edge-browser | grep "not found"     # 应当没有输出
```

Chromium 任选其一：

```bash
# A. 系统包（发行版而异）
sudo apt-get install -y chromium            # 或 chromium-browser
# B. Playwright 管理的 Chromium（装到 ~/.cache/ms-playwright，边缘会自动发现）
npx playwright install chromium
# C. Google Chrome 官方 deb
```

虚拟声卡（可选，要声音才装）：

```bash
sudo apt-get install -y pulseaudio pulseaudio-utils
```

### 3.3 Chromium 发现顺序

`--chromium <path>` → 环境变量 `RIG_CHROMIUM` → `~/.cache/ms-playwright/*/`（完整 Chromium 优先于 headless shell，同类取版本最新）→ `PATH` 里的 `chromium`、`chromium-browser`、`google-chrome`、`google-chrome-stable`。

> 完整 Chromium 优于 headless shell：投屏与音频路径需要它。

## 4. 便携放置（不装到系统）

适用于：没有 root、不想动系统包、要把整套环境搬走。

### 4.1 Chromium

任意位置解压/放置，用 `--chromium /path/to/chrome` 或 `RIG_CHROMIUM` 指向它即可。Playwright 的浏览器目录也可整体拷贝，只要 `~/.cache/ms-playwright` 结构不变就会被自动发现。

### 4.2 PulseAudio（本项目已验证的做法）

把 `.deb` 解包到仓库内的 `.temp/pulseaudio/`，**不安装**：

```bash
mkdir -p .temp/pulsedebs .temp/pulseaudio && cd .temp/pulsedebs
apt-get download pulseaudio pulseaudio-utils            # 以及 ldd 报缺的依赖库包
for f in *.deb; do dpkg -x "$f" ../pulseaudio; done
```

缺哪个库补哪个（本机还额外需要 `libabsl`、`libltdl7`、`libspeexdsp1`、`libtdb1`、`libwebrtc-audio-processing-1-3`、`libsnapd-glib-2-1` 这些包，**随发行版版本变化**）。

使用时必须导出下面这组环境变量，让 `pulseaudio`/`pactl` 能被边缘找到、且不去连系统总线：

```bash
PA=$PWD/.temp/pulseaudio; RUN=$PWD/.temp/pulse-run
export PATH="$PA/usr/bin:$PATH"
export LD_LIBRARY_PATH="$PA/usr/lib/x86_64-linux-gnu:$PA/usr/lib/x86_64-linux-gnu/pulseaudio:$PA/usr/lib/pulse-17.0+dfsg1/modules"
export XDG_RUNTIME_DIR="$RUN" PULSE_RUNTIME_PATH="$RUN"
export DBUS_SESSION_BUS_ADDRESS="unix:path=/nonexistent" DBUS_SYSTEM_BUS_ADDRESS="unix:path=/nonexistent"
export PULSE_SERVER="unix:$RUN/native" PULSE_SINK=rigsink
```

`scripts/with-pulse.sh <命令…>` 把上面这组变量只作用于被运行的命令（起守护进程、建 `rigsink`、再 `exec` 命令，**不改 `HOME`**），`scripts/test.sh it` 检测到便携 PulseAudio 时会自动使用它。`scripts/edge-lan.sh` 已经封装了「起便携 PulseAudio + 建 `rigsink` 虚拟声卡 + 起边缘」的完整流程，**直接用它**。

> ⚠ `edge-lan.sh` 为了给 PulseAudio 隔离配置会改写 `HOME`。之后若在同一 shell 里跑集成测试，要先 `export HOME=/root`（或你的真实家目录），否则找不到 `~/.cache/ms-playwright` 下的 Chromium，`git` 也会报 dubious ownership。更稳妥的做法是只把这些变量用在启动 PulseAudio 与边缘的那一条命令上，而不是整个 shell。

边缘自己会做「虚拟声卡自愈」：探活失败时 `pulseaudio --start`，仍不行则 `--kill` 后重启一次，最后以「`rigsink` 出现在 sink 列表」为就绪判据。`PATH` 里找得到 `pactl` 就认为音频可用（`av_available`）。

### 4.3 边缘二进制本身

边缘二进制**动态链接**系统的 FFmpeg 库，所以「完全便携」意味着把这些 `.so` 一并带走并用 `LD_LIBRARY_PATH` 指向它们：

```bash
ldd rig-edge-browser | awk '/=>/ {print $3}' | grep -E "libav|libsw|libx26"   # 列出要带的库
LD_LIBRARY_PATH=/opt/rig/lib /opt/rig/rig-edge-browser --listen 127.0.0.1:39871 ...
```

> **未验证**：我们没有在一台干净机器上做过整包搬迁测试。`ldd` 列出的依赖会连带很多传递依赖（`libavfilter` 等），按 `ldd` 输出逐个确认。

## 6. 环境变量速查

| 变量 | 作用 |
|---|---|
| `RIG_EDGE_TOKEN` | 同 `--token` |
| `RIG_EDGE_PROFILE_DIR` / `RIG_EDGE_CACHE_DIR` | 同 `--profile-dir` / `--cache-dir` |
| `RIG_CHROMIUM` | Chromium 可执行文件路径 |
| `RIG_CHROMIUM_NO_SANDBOX=1` | 强制禁用 Chromium 沙箱。root 运行时本来就会自动禁用（Chromium 在 root 下无法启用沙箱），其余情况默认保留沙箱 |
| `RIG_EDGE_UA` / `RIG_EDGE_TZ` / `RIG_EDGE_LANG` | 覆盖 UA（整串）、时区（默认 Asia/Tokyo）、语言（默认 ja-JP） |
| `RIG_HLS_SINGLE=h264\|hevc` | 只出一种 HLS 版本（默认双版本） |
| `RIG_PUMP_FULL_ONLY=1` | 帧泵只用整页帧，丢弃内容帧（A/B 与故障回退） |
| `RIG_EDGE_DEBUG` | 打印标签页挂载的调试行 |
| `RIG_EDGE_IT=1` | **仅测试**：启用真 Chromium 集成测试 |
| `PULSE_SERVER` / `PULSE_SINK` 等 | 便携 PulseAudio，见 §4.2 |
| `CARGO_TARGET_DIR` | `source scripts/local-env.sh` 会重定向到 `.temp/target` |
