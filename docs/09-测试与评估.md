# 09 测试与评估

## 1. 测试分层

| 层 | 范围 | 怎么跑 | 当前状态 |
|---|---|---|---|
| Rust 单元测试 | 边缘核心、发布启动器、协议与评估库，含假 CDP | `scripts/test.sh unit` 或 `cargo test --all` | CI 会运行 |
| 真 Chromium 集成测试 | `crates/rig-edge-browser/tests/edge_it.rs`，真浏览器 + 真 HTTP/WS | `scripts/test.sh it` | 依赖真实 Chromium；音视频用例另需媒体依赖 |
| Python 汇总工具自测 | `tests/eval_report/` | `scripts/test.sh py` 或 unittest 命令 | CI 会运行 |
| 评估夹具校验 | `eval/verify_fixtures.py` | 真实 Chromium + Playwright Python | 按需运行；确定性校验任务初态、标准答案和陷阱路径，不调用模型 |

**CI 运行 fmt、clippy、`cargo test --all`（不含 `RIG_EDGE_IT`）和 Python 自测，不跑真浏览器集成测试。** `scripts/test.sh` 是项目测试启动器：`unit`（默认）运行 Cargo 全部测试、`it` 运行真浏览器集成套件、`av` 只运行音视频用例、`py` 运行 Python 汇总工具自测、`all` 运行含浏览器的 Rust 测试及 Python 自测。提交前本地完整门禁入口为 `scripts/local-gate.sh`。

## 2. 提交前必须全绿

```bash
bash scripts/local-gate.sh
```

没装 Rust 或浏览器依赖时，**报告「未验证」，不要臆造通过**。

## 3. 集成测试怎么跑

`unit` 始终跳过真 Chromium 测试。`it`、`av`、`all` 启用真 Chromium 集成测试。可以使用 `scripts/test.sh it`，或运行 `RIG_EDGE_IT=1 cargo test -p rig-edge-browser --test edge_it`。

- 需要真 Chromium：默认从 `PATH` 查找。可设置 `RIG_EDGE_TEST_CHROMIUM_DIR` 指向直接包含 `chrome` 或 `chromium` 的绝对目录。自拉与挂靠用例都优先使用该浏览器。
- **音视频用例**（`edge_av_and_image_clipboard`）需要 PulseAudio、`ffprobe` 和 `ffmpeg` 命令行。运行 `scripts/prepare-media.sh` 后，`scripts/test.sh` 优先使用 `RIG_EDGE_TEST_PULSEAUDIO_DIR`，其次使用 `${RIG_MEDIA_DIR:-.temp/media-deps}/root/` 内的 PulseAudio，最后由边缘程序查找系统安装。放置结构见 [04 §4.2](04-依赖与环境.md)。
- 用例**串行**执行（每个都要拉 Chromium，全并行会互相挤兑产生假失败）。
- 每个用例启动自己的边缘进程，测试辅助函数提供测试令牌和请求认证。结束时终止测试进程组，并清理 `rig-edge-<pid>`、`rig-edge-<pid>-uploads`、`rig-edge-<pid>-pulse` 和 `rig-edge-hls-<pid>`。

## 4. 写测试的要求

- **先写测试，再写实现**；一次只做一个改动。不删除、不弱化已有断言。
- 修 bug：先写能**复现**的失败测试，再修，再确认通过。
- **探针先自证**：夹具必须在源头产生可测信号，测量点要用已知有信号的输入校准过（[03 §六](03-关键技术难点与解决.md)）。
- 带令牌的部署形态必须有**真浏览器端到端探针**（只测无令牌回环会漏掉整类问题，P32）。
- **测完检查 `/tmp`**：新增的测试若留下 `rig-*` 目录，是泄漏，要修。

## 5. 度量规范

- **评估相关的数字（准确率、token、延迟）必须来自实际运行，注明环境**，不凭印象写进文档。
- 已有度量都标注为：debug 构建、本地回环、单次或 n=20、页面无副作用。release 与真实网络**未测**。
- 当前项目运行与测试**没有对接模型来测 token**；`RunRecord` 和 `scripts/eval_report.py` 能汇总运行器实际写入的 token 字段，但不会自行调用模型或测算 token。2026-11-18 的历史模型实验确实记录了模型 token，详见 [历史 G1 报告](EVAL_REPORT_2026-11-18.md)；这些历史数字不代表当前测试或当前运行的模型 token 用量。宿主接入时需由模型服务/运行器真实采集（[07 §3.3](07-智能体接入方案.md)）。

已测数据（2026-11-21，debug、本地回环、n=20，来自 2026-11-21 交接文档的实测，该文档已并入本文集，原文见 git 历史 `docs/HANDOFF_2026-11-21.md`）：

| 场景 | 改前 | 单元素复核后 | 解耦后 |
|---|---|---|---|
| 小页点击 `act` p50 | 130.0 ms | 101.1 ms | 65.9 ms |
| 大页（约 550 元素）点击 `act` p50 | 未测 | 246.2 ms | 67.8 ms |
| 之后 `observe(since)`（页面没变） | — | — | 大页 2.2 ms，小页 1.5 ms |

大页 `observe` 完整采集约 183 ms（87 次 CDP；大头是整棵 AX 树 + DOM 映射约 148 ms）。**页面确有变化时 `observe(since)` 的耗时未测。**

## 6. 感知层评估（`rig-eval` + `eval/`）

目的：证明「语义快照比直接发截图更省、更准、更可控」——这是需要被证明的，不是假设。

| 对象 | 内容 |
|---|---|
| `crates/rig-eval` | 任务加载/模型目标校验、运行记录与指标汇总（`metrics::summarize`）、泄密检测（`leak::find_leaks`）；不含模型调用或浏览器驱动运行器 |
| `eval/tasks/web` | 评估任务定义 |
| `eval/fixtures/web` | 测试页面 |
| `eval/results/` | 历史运行证据，**只读，不改写历史** |
| `eval/verify_fixtures.py` | 真实 Chromium + Playwright 下对任务判据、标准答案和陷阱路径作确定性校验，不调用模型 |
| `scripts/eval_report.py` | `RunRecord`（JSON Lines）汇总，**不自动下结论** |

方法要点（详见 [EVAL.md](EVAL.md)）：

- 历史模型评估应比较多种 `Mode`，同一任务每个 Mode 至少 N≥5 次，并报告均值与分布；固定并记录模型版本、温度、步数上限、提示词。
- 模型运行器应对每一步模型输入做泄密检测并记录 `leaked_secret`；`rig-eval` 提供检查函数，不负责构造或发送模型输入。
- 观察延迟须包含 Observer 全部耗时（取树、过滤、渲染、图像生成）。
- G1 v2 已于 2026-11-18 作出方向决定；当前阶段状态和历史依据见 [EVAL.md](EVAL.md) 与 [G1 报告](EVAL_REPORT_2026-11-18.md)。

历史结论见 [EVAL_REPORT_2026-11-18.md](EVAL_REPORT_2026-11-18.md)、`P0_*`、`P1_*`（当时的实测，只读）。**评估使用的模型与凭证属于必须停下来问的事项**（`CLAUDE.md`）。

## 7. 常见测试问题

| 现象 | 处理 |
|---|---|
| `edge_av_and_image_clipboard` 在 PulseAudio 断言失败 | 环境缺 PulseAudio，见 [04 §4.2](04-依赖与环境.md) |
| 用例报找不到 Chromium | 检查 `PATH`；或设置 `RIG_EDGE_TEST_CHROMIUM_DIR=/path/to/chrome-linux64` |
| 偶发 `media::tests::single_rendition_builds_one_output` 失败 | 疑似修改进程级环境变量与并行单测互扰（未验证）；单独重跑确认 |
| 测试后 `/tmp` 有 `rig-*` 目录 | 先确认没有残留的边缘进程；再清理；若是新增用例泄漏，修用例 |
| 清进程退出码 144 | 你用了 `pkill -f`/`pgrep -f` 且模式串出现在自己的命令行里。用 `$!` 或让包装脚本 `exec` |
