## 1. 测试分层

| 层 | 范围 | 怎么跑 | 现状（2026-11-22，本机） |
|---|---|---|---|

> 脚本入口：`scripts/test.sh [unit|it|av|py|all]`；提交前完整门禁 `bash scripts/local-gate.sh`（详见 [05 §1.3](05-编译部署与运行.md)）。

## 3. 集成测试怎么跑

`unit` 始终跳过真 Chromium 测试。`it`、`av`、`all` 启用真 Chromium 集成测试。可以使用 `scripts/test.sh it`，或运行 `RIG_EDGE_IT=1 cargo test -p rig-edge-browser --test edge_it`。

- 需要真 Chromium：默认从 `PATH` 查找；便携浏览器可通过 `RIG_EDGE_TEST_CHROMIUM_DIR` 指向直接包含 `chrome` 或 `chromium` 的目录。测试会把该目录作为 `--chromium-dir` 传给边缘子进程，挂靠用例也从同一目录启动浏览器；不自动探测 HOME 或 Playwright。
- **音视频用例**（`edge_av_and_image_clipboard`）需要 PulseAudio fixture 和 `ffprobe`。`scripts/test.sh` 会在 `.temp/pulseaudio/` 存在时自动使用；也可用 `RIG_EDGE_TEST_PULSEAUDIO_DIR=/path/to/unpacked` 显式指定。放置结构见 [04 §4.2](04-依赖与环境.md)。测试目录参数由 `RIG_EDGE_TEST_*` 环境变量控制。
- 用例**串行**执行（每个都要拉 Chromium，全并行会互相挤兑产生假失败）。
- 每个用例启动自己的边缘进程，测试辅助函数提供测试令牌和请求认证。结束时终止测试进程组，并清理 `rig-edge-<pid>`、`rig-edge-<pid>-uploads`、`rig-edge-<pid>-pulse` 和 `rig-edge-hls-<pid>`。

## 4. 写测试的要求

- **先写测试，再写实现**；一次只做一个改动。不删除、不弱化已有断言。
- 修 bug：先写能**复现**的失败测试，再修，再确认通过。
- **探针先自证**：夹具必须在源头产生可测信号，测量点要用已知有信号的输入校准过（[03 §六](03-关键技术难点与解决.md)）。
- 带令牌的部署形态必须有**真浏览器端到端探针**（只测无令牌回环会漏掉整类问题，P32）。
- **测完检查 `/tmp`**：新增的测试若留下 `rig-*` 目录，是泄漏，要修。

## 5. 度量规范

- **评估相关的数字（准确率、token、延迟）必须来自实际运行，注明环境**，不凭印象写进文档。
- 已有度量都标注为：debug 构建、本地回环、单次或 n=20、页面无副作用。release 与真实网络**未测**。
- 本仓库**没有量过模型 token**，只量过传输体积与延迟；宿主接入时需要自己量（[07 §3.3](07-智能体接入方案.md)）。

已测数据（2026-11-21，debug、本地回环、n=20，来自 2026-11-21 交接文档的实测，该文档已并入本文集，原文见 git 历史 `docs/HANDOFF_2026-11-21.md`）：

| 场景 | 改前 | 单元素复核后 | 解耦后 |
|---|---|---|---|
| 小页点击 `act` p50 | 130.0 ms | 101.1 ms | 65.9 ms |
| 大页（约 550 元素）点击 `act` p50 | 未测 | 246.2 ms | 67.8 ms |
| 之后 `observe(since)`（页面没变） | — | — | 大页 2.2 ms，小页 1.5 ms |

大页 `observe` 完整采集约 183 ms（87 次 CDP；大头是整棵 AX 树 + DOM 映射约 148 ms）。**页面确有变化时 `observe(since)` 的耗时未测。**

## 6. 感知层评估（`rig-eval` + `eval/`）

目的：证明「语义快照比直接发截图更省、更准、更可控」——这是需要被证明的，不是假设。

| 对象 | 内容 |
|---|---|
| `crates/rig-eval` | 评估运行器：任务定义、指标汇总（`metrics::summarize`）、泄密检测（`leak::find_leaks`） |
| `eval/tasks/web` | 评估任务定义 |
| `eval/fixtures/web` | 测试页面 |
| `eval/results/` | 历史运行证据，**只读，不改写历史** |
| `scripts/eval_report.py` | `RunRecord`（JSON Lines）汇总，**不自动下结论** |

方法要点（详见 [EVAL.md](EVAL.md)）：

- 比较多种 `Mode`（语义树、截图、树+图等），同一任务每个 Mode 至少 N≥5 次，报均值与分布。
- 固定模型版本、温度、步数上限（建议 15）、提示词，写进报告。
- 对每一步送入模型的内容做**泄密检测**，记录 `leaked_secret`。
- 观察延迟包含 Observer 全部耗时（取树、过滤、渲染、图像生成）。
- 决策门 G1（P2 末尾）：达标才继续投入像素兜底等后续工作。

历史结论见 [EVAL_REPORT_2026-11-18.md](EVAL_REPORT_2026-11-18.md)、`P0_*`、`P1_*`（当时的实测，只读）。**评估使用的模型与凭证属于必须停下来问的事项**（`CLAUDE.md`）。

> **待核实**：`rig-eval` 运行器对 `Done.frame_id` 新语义（动作所基于的校验帧，而非动作后新帧）的使用尚未核对。

## 7. 常见测试问题

| 现象 | 处理 |
|---|---|
| `edge_av_and_image_clipboard` 在 PulseAudio 断言失败 | 环境缺 PulseAudio，见 [04 §4.2](04-依赖与环境.md) |
| 用例报找不到 Chromium | 检查 `PATH`；或设置 `RIG_EDGE_TEST_CHROMIUM_DIR=/path/to/chrome-linux64` |
| 偶发 `media::tests::single_rendition_builds_one_output` 失败 | 疑似修改进程级环境变量与并行单测互扰（未验证）；单独重跑确认 |
| 测试后 `/tmp` 有 `rig-*` 目录 | 先确认没有残留的边缘进程；再清理；若是新增用例泄漏，修用例 |
| 清进程退出码 144 | 你用了 `pkill -f`/`pgrep -f` 且模式串出现在自己的命令行里。用 `$!` 或让包装脚本 `exec` |
