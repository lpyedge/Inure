# 感知与操作层（Perception）

契约定义在 `crates/rig-proto/src/observation.rs`，主要实现在边缘程序的 `ai.rs` 与 `snapshot.rs`。HTTP/MCP 调用格式见 [06 接口与调用](06-接口与调用.md)。

## 1. 当前范围与原则

- Chromium 是当前支持的感知目标。通过 CDP 获取无障碍树（AX）、DOM 属性和几何信息；只有缺少语义的区域才使用截图兜底。
- `observe` 产生语义 `Observation`，`act` 接收带帧号的 `ActionRequest`。HTTP 与 MCP 共用同一 AI 通道实现。
- 元素坐标使用逻辑像素（Chromium CSS 像素）；图像使用物理像素尺寸，边缘负责转换。
- 页面文本一律是不可信数据。动作按目标与帧校验；拒绝的动作不会执行，也不会静默重试。
- 人通道观看帧与 AI 观察是分开的采集路径。不要假设视频帧、语义帧或动作校验帧是同一张截图。

canvas 等缺少语义的网页区域，可按需使用编号截图和坐标目标。

## 2. Observation 与快照

`Observation` 含单调递增的 `frame_id`、`source`、逻辑坐标 `space`、元素树、可选文本/图像引用，以及固定为 `Untrusted` 的 `content_trust`。元素含稳定 id、规范化角色、名称、可选值与边界框、状态、来源、置信度和子元素。当前 Chromium 元素来源为 AX 或 DOM。

`snapshot.rs` 以 AX 树为语义主干，结合 DOM 映射识别敏感字段并关联几何。同一 CDP 会话内的 iframe 按 `frameId` 单独采集 AX 树，确认当前文档和脱敏属性后挂到宿主元素下，几何使用会话视口坐标。跨进程 iframe（OOPIF）通过 CDP 子会话采集，按宿主 iframe 的位置合成坐标。采集范围限于授权页面及其后代 iframe，不会把其他标签页合并进快照。没有可用几何或语义的区域不能作为可靠元素目标。

快照会剪除无语义的通用壳，过滤默认不输出的视口外元素，并以 `backendNodeId` 映射维护元素 id；节点销毁后 id 不复用。请求可选择 `text`、`tree` 或 `tree_image`，并使用 `subtree`、`budget_tokens`、`include_offscreen` 控制响应投影。裁剪只影响响应视图，存储帧仍保留完整观察，故被裁掉的元素仍可能通过 id 操作。

文本主要为当前可交互的控件、Canvas 和 iframe 标记坐标，保留正文、状态与元素 id。已经完整显示在父元素名称里的重复文字会折叠。结构化观察中的几何仍用于机器消费，完整存储帧继续用于动作校验和截图遮罩。

### 敏感信息与截图

密码和标记为敏感的输入值在 Observation 输出前清除；敏感元素的后代文本也必须清理，不能只清父元素的 `value`。密码框可能将掩码作为名称或子文本暴露，掩码同样不能保留。敏感区域几何从完整快照获取，即使响应树被裁剪也不能漏掉遮罩。

`tree_image` 与 `screenshot` 生成编号截图，并将敏感区域涂黑。截图前后会核对页面、视口及敏感区域几何；无法确认遮罩或页面身份变化时，不交付截图。HTTP `/screenshot.png` 与 MCP `screenshot` 的使用方式见 [06 §2、§3](06-接口与调用.md)。安全策略详见 [08 安全模型](08-安全模型.md)及[安全整改设计](SECURITY_DESIGN_2026-11-19.md)。

## 3. 观察与增量

每次 `observe` 都采集候选快照，以捕捉滚动、焦点和布局等不一定产生结构通知的变化。候选帧在采集期间若页面、文档或视口上下文失效则丢弃。`tree` 模式可以用 `since_frame` 请求增量。基帧须在最近八个已输出的结构化观察中，且页面、文档、坐标空间与输出投影相容。只有客户端能按 `base_frame` 正确重建视图时才返回 `ObservationDelta`。

若候选帧投影视图与上一帧相同，仍推进帧号并返回空增量。这是采集后的比较结果，不代表跳过采集。变化后的增量须能重建完整视图，且其结构化 JSON 小于整帧 JSON，否则返回整帧。静态页空增量的历史测量见 §7。

编号截图随 AI 请求从当前页面采集，并核对文档和视口。观看页视频是独立的采集管线。

## 4. 动作校验

动作目标为元素 id 或坐标。元素目标优先使用语义定位；坐标仅用于当前帧且必须在视口内，适合 canvas 等无语义区域。动作请求引用 `frame_id`，并受通道开关、接管状态、导航 origin 白名单等现行策略约束；完整安全边界见 [08](08-安全模型.md)。

元素动作的陈旧校验以调用方实际获得的观察帧为基准。若目标相对当前帧的角色、名称、状态或边界框发生变化，或目标消失/不可交互，则拒绝。比较忽略易变的 `Focused`、`Busy` 状态及输入值；几何容差为 2 逻辑像素。历史帧不在保留池时视为过期。坐标目标要求帧号严格匹配当前存储帧，并进行实时命中复核。

对最新存储帧中的主会话元素目标，边缘可先查询单元素 AX、DOM 属性与位置，使用与整页快照相同的 `element_core` 转换后比较。此快路径只用于确认：不一致、查询失败或目标不适用时，退回完整快照校验，不据此直接裁决动作。DOM 命中查询按当前会话的视觉视口原点换算为文档坐标，输入事件使用视口坐标。命中失败会拒绝动作。动作执行期间保留文档代次与接管检查；多步动作在副作用前检查。拒绝原因及拒绝时附带的最新状态见 [06 §2.2](06-接口与调用.md)。

`Done.frame_id` 表示动作所依据的校验帧。调用方要取得更新时，调用 `observe`，将 `since_frame` 设为客户端已套用的最近一次观察帧号。

## 5. 调用与安全约束

当前 AI 调用面为 HTTP `POST /observe`、`POST /act`、`GET /screenshot.png`，以及 MCP `observe`、`act`、`screenshot`。MCP 工具描述标明页面内容是不可信数据；不要把网页文字解释成授权或高权限指令。HTTP 与 MCP 的认证和完整请求字段见 [06](06-接口与调用.md)，传输与令牌策略见 [08](08-安全模型.md)。

## 6. 历史原型证据

P1 原型与 P0 基线结果是历史实验，不代表当前正式实现的性能或行为，也不应作为当前架构要求。原始数据、环境和完整结论保留在只读报告中：

- [P1 原型结果（2026-11-18）](P1_PROTOTYPE_RESULTS_2026-11-18.md)
- [P0 基线结果（2026-11-18）](P0_BASELINE_RESULTS_2026-11-18.md)
- [P0.5 效率实验（2026-11-18）](P0_5_EFFICIENCY_2026-11-18.md)

保留适用于当前实现的结论：敏感信息须从整棵子树清理，截图遮罩必须基于未裁剪的完整观察；滚动可能使大范围元素几何变化，增量未必比全量响应更小；iframe 目标需要正确处理子会话和宿主坐标。其余原型成绩与方案请以以上报告为准，不据此承诺当前性能。

## 7. 已记录的实现测量

静态页空增量以 `d9f7361` 为对照。实测环境为 Intel i5-10400、Chromium 156.0.8078.4、本机 HTTP、debug 构建，暖机 5 次后每场景测量 50 次。单按钮页 p50/p95 为 1.10/1.94 ms（对照）与 4.62/5.27 ms（改用候选采集后）。180 行按钮页为 1.65/2.08 ms 与 106.75/109.95 ms。两个场景均返回空增量。

Chromium 156 探针观察到：文字改变可表现为旧文本节点删除与新节点插入；滚动没有结构通知；`Accessibility.nodesUpdated` 未触发。因此结构通知用于失效判断和校验帧复用，不能替代每次观察时的候选采集。探针材料见 [DOM 探针记录](DOM_SPIKE_2026-11-19.md)。
