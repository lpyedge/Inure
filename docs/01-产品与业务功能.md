# 01 产品与业务功能

## 1. 一句话定位

**一个 Rust 二进制 `rig-edge-browser`，直连 Chromium（CDP），把同一个真实浏览器同时开放给两类消费者：**

- **AI 通道**：把页面压成紧凑的语义快照给智能体看；智能体用「帧号 + 元素 id」下达动作，边缘执行前先校验。
- **人通道**：把画面（和声音）流给人看，并把人的鼠标、键盘、剪贴板送回页面。

两个通道操作的是**同一个浏览器、同一个登录态**。人能看到 AI 在做什么，也能随时把控制权抢回来。

同机（stdio / 回环 HTTP）或局域网（HTTPS + 令牌）直连即完整形态，不依赖任何中转服务。

## 2. 解决什么问题

| 场景 | 痛点 | 本项目的做法 |
|---|---|---|
| 让 AI 操作真实网站 | 直接给模型发截图又贵又不准；自己拼 Playwright 脚本要为每个站点写选择器 | 从浏览器无障碍树取语义，元素有稳定 id；没有语义的区域（canvas 等）才退回编号截图 |
| AI 操作需要人盯着 | 看不到 AI 在干什么，出错无法及时介入 | 观看页实时显示画面、AI 指针与意图；人一点击就能强制接管 |
| 需要登录态 / 人工验证 | 验证码、扫码、二步验证 AI 过不去 | 人和 AI 共用同一浏览器，人来过验证，AI 接着干；登录态可持久化跨重启 |
| 智能体宿主有自己的界面 | 想把浏览器画面嵌进智能体的 Web UI | 观看页可内嵌 iframe，宿主自动授权，无需人工输入令牌 |

## 3. 使用形态

| 形态 | 谁用 | 怎么启动 | 详见 |
|---|---|---|---|
| 人在本机看 | 人 | `--human` 后用浏览器打开观看页 | [05 §运行配方](05-编译部署与运行.md) |
| AI 本机子进程（MCP stdio） | 智能体宿主 | 宿主以子进程拉起 `--stdio`，走 stdin/stdout JSON-RPC | [06 §MCP](06-接口与调用.md) |
| AI 经局域网（HTTPS） | 脚本 / 智能体 | `--listen` 绑局域网地址 + 令牌，经 HTTPS 调 `/observe` `/act` | [06 §HTTP](06-接口与调用.md) |
| 人 + AI 协作 | 两者同时在线 | 同一进程同时开两个通道 | 本文 §6 |
| 内嵌进智能体 Web UI | 智能体宿主的用户 | iframe 嵌观看页，`postMessage` 自动授权 | [06 §内嵌](06-接口与调用.md) |

四种形态共用同一份感知与动作语义，差别只在传输和外壳。

默认 AI 通道开启、人通道关闭；`--no-ai` 才关闭 AI，`--human` 才默认开启人通道。凡启动 HTTP 服务（包括 `--stdio --human`）都必须提供非空 `--token` 或 `RIG_EDGE_TOKEN`。

## 4. AI 通道：能做什么

### 4.1 观察（observe）

返回当前页面的语义快照：每个元素有稳定 id（如 `e12`）、角色、名称、状态、位置。

| 能力 | 说明 |
|---|---|
| 三种输出粒度 | `text` 只回紧凑文本（最省）；`tree` 文本 + 结构化树（默认）；`tree_image` 再附编号截图 |
| 增量观察 | 带上次的 `since_frame`：页面没变回空增量、不重新采集；变了回增量或整帧 |
| 子树与预算 | `subtree` 只看某元素；`budget_tokens` 按预算裁剪响应（被裁元素凭 id 仍可操作） |
| 视口外元素 | 默认不带，`include_offscreen` 才带 |
| 跨 iframe | 同源与跨源子帧都纳入，坐标统一换算 |
| 敏感值脱敏 | 密码框与敏感字段整棵子树清值，截图上打黑块 |
| 只看当前标签 | 快照只收录人当前看的标签页，不把其他标签送进 AI 视野 |

### 4.2 动作（act）

| 动作 | 说明 |
|---|---|
| `click` | 左/中/右键，单击/双击，目标可以是元素或坐标 |
| `hover` | 悬停 |
| `type` | 输入文本，可先点击目标、可选提交（回车） |
| `key` | 按键或组合键（如 `Control+A`） |
| `scroll` | 滚动，目标可选 |
| `select` | 原生下拉框选值（先验证所有值，再改值） |
| `upload` | 给文件框喂文件，文件须在边缘的上传目录内（见 [08](08-安全模型.md)） |
| `navigate` | 导航，受 origin 白名单约束 |

动作的三个保证：

1. **执行前校验**：帧陈旧、元素消失、不可交互、越界，一律**不执行、不静默重试**，返回明确拒绝原因。
2. **被拒时附最新状态**：拒绝回包里同时带最新的增量或整帧，AI 能直接继续，不用自己再要数据。
3. **操作与呈现解耦**：`act` 只回答「有没有执行」；页面变成了什么样，调用方按需 `observe(since_frame)`。

### 4.3 截图

`screenshot` 返回编号 PNG，敏感区域涂黑。定位是**兜底**：语义不足的区域（canvas、图片按钮）才用。

## 5. 人通道：能做什么

观看页是一个原生 DOM 页面，形态类似浏览器本身。

| 类别 | 功能 |
|---|---|
| 浏览器外壳 | 标签条（新建/关闭/切换）、地址栏（含搜索归一化）、前进后退重载、页内查找、打印（取回 PDF） |
| 两种呈现 | **视频模式**：远端画面（WebRTC 主路，WS 的 JPEG 帧兜底）；**DOM 镜像模式**：在观看端重建页面，低带宽、文字可原生选取。可自动按页面内容切换，也可手动锁定 |
| 声音 | 页面声音走虚拟声卡，经 WebRTC（Opus）或 HLS（AAC）送到观看端 |
| 输入 | 鼠标（含右键、双击、拖选）、键盘（物理键位 + 修饰键）、输入法整段送入、观看页快捷键（Ctrl+F/L/T/W/R 等） |
| 剪贴板 | 文本与图片双向。复制是一次请求/回应，不做后台同步，不覆盖用户在外部的新复制 |
| 右键菜单 | 观看端自绘：复制、贴上、全选、复制图片、后退、前进、重载 |
| 分辨率 | 跟随窗口或固定尺寸 |
| 通道开关 | 在界面上开关 AI 通道与人通道 |
| AI 指针 | AI 执行时叠加显示 AI 指针、轨迹、点击波纹和意图标签（如「点击 登录 [e5]」），不注入页面 |

> 观看页每一项的实现细节与踩坑见 [EDGE_BROWSER.md §9](EDGE_BROWSER.md)。

## 6. 人机协作模型：待命 / 执行 / 强制接管

前提共识：AI 的操作速度必然慢于人。所以人和 AI 共存**不靠同时抢同一个页面**，而靠状态分工。

| 状态 | 含义 | 边缘行为 |
|---|---|---|
| 待命 | AI 已接入，无指令在执行 | 不做任何识别处理（不拍快照、不跑 AX） |
| 执行 | 有 AI 调用在途 | 正常处理；人侧**遮蔽输入**并显示 AI 指针 |

- **保持窗**：最后一个在途调用结束后 2 秒才回待命，覆盖「一条指令拆成多个调用」的间隔，避免遮蔽反复闪烁。
- **强制接管**：遮蔽期间人点击或敲键，观看页弹出提示 “The AI is performing an action. Take over control?”（按钮 “Take over” / “Keep waiting”）。选 Take over：在途动作立即中止，返回 `Aborted(user_takeover)`；AI 须**重新 observe** 才能再 `act`；MCP 客户端额外收到停止指示和通知 `notifications/rig/control_taken_over`。
- **关闭 AI 通道**等同接管：撤销当前执行代次，重新开启后同样须先 `observe`。
- 接管只中断指令，不断开连接、不动授权。

## 7. 浏览器来源与持久化

| 项 | 说明 |
|---|---|
| 自拉起 | 默认。按 `PATH` 查找 Chromium；也可用 `--chromium-dir` 指定直接含 `chrome` 或 `chromium` 的目录。使用独立 profile；边缘退出时关闭它 |
| 挂靠 | `--cdp-url`：连接已有的 Chromium；边缘退出**只断开，绝不关闭**对方 |
| 持久化 | `--profile-dir` 指向 Chromium 用户数据目录：登录态、Cookie、存储、扩展、保存的密码都在里面；整目录搬到新环境即可续用 |
| 可弃缓存 | `--cache-dir`：磁盘缓存，迁移时可不带 |
| 一次性模式 | 都不给时用进程专属临时目录，**退出时清理**，不留登录态 |
| 人格 | 自拉起的浏览器不暴露 headless/CDP 形态：UA（含 userAgentData）、时区、语言可配置 |

## 8. 非目标（明确不做）

- 只支持 **Chromium**；不做 Firefox、Safari、iOS、桌面 RDP/VNC。
- 不为通用像素理解做 OCR 或视觉模型；像素只是语义缺失时的兜底。
- 人通道不做**文件粘贴**（观看端读不到使用者本机文件）；文件靠 AI 通道的 `upload`。
- 不做多租户隔离：按**个人/受信环境、人工监督的单人工具**设计。
- 网关、中转、反向接入不在本仓库。
- 不替智能体做任务规划：本项目只提供「看」和「做」，宿主负责决策。
